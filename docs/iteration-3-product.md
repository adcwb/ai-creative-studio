# 映创第三轮产品范围与验收标准

基线为 `6e30ff6`。本轮只进行本地实现和验证，不推送、不创建 PR、不部署。本文定义产品目标与验收要求，不代表功能或测试已经通过。

## 本轮目标

交付两个可核对的增量：修复用户反馈的桌面底部不齐/内容突出问题；在默认模拟模式之外，增加一种明确官方协议的图像服务适配器，并完成模式状态、真实 HTTP 请求、结果校验与持久化、读取保存和错误恢复的业务闭环。

保留映创品牌、三个创作模板、比例/风格、任务详情、失败关联重试、素材检索和演示空间。图像服务只选一种协议和一个固定模型，不增加模型市场、照片上传、图像编辑、批量生成、短剧/漫剧、账单、数据库迁移或生产认证。所有交付测试使用本地 HTTP 假服务和合成图片，不创建凭据、不在聊天中索取密钥、不执行付费生成。

## 图像服务与范围

新增服务标识为 `openai-images`，保留 `mock-svg`。本轮选定 OpenAI Images 的 `POST /v1/images/generations` 与固定模型 `gpt-image-2-2026-04-21`；不是所有“OpenAI 兼容”接口的通用适配器。官方接口列明此模型、PNG 输出、自定义尺寸与默认 base64 图片响应；GPT Image 的风格应写入提示词，不使用旧模型的 `style` 或 `response_format` 字段。依据：[Create image 官方接口](https://developers.openai.com/api/reference/resources/images/methods/generate)。固定快照存在于 [GPT Image 2 官方模型页](https://developers.openai.com/api/docs/models/gpt-image-2)，本轮不据此声称其为最新或最佳模型。

产品约束为单张、PNG、`quality=low`，不提供额外价格或质量档位。现有比例准确映射如下，不允许把近似尺寸静默标成原比例：

| 界面比例 | 外部请求尺寸 | 用户含义 |
| --- | --- | --- |
| `1:1` | `1024x1024` | 方形 |
| `4:5` | `1024x1280` | 竖版 |
| `16:9` | `1536x864` | 横版 |

`kind` 与 `style` 保留在业务记录中，并转成外部提示词的一部分。测试检查它们被传给适配器，不以本地假服务图片证明真实模型遵循了风格或理解了描述。

## 模式与用户路径

服务选择和密钥只由后端配置。前端不接收、保存或提交密钥，不新增“连接账号”“购买额度”或凭据创建入口。默认启动继续为可用的模拟模式，无需模型凭据。

后端提供 `GET /api/v1/capabilities` 作为当前模式来源，冻结响应如下：`{provider, mode, ready, model?, reason_code?, message}`。`provider` 为 `mock-svg`、`openai-images` 或 `unavailable`，`mode` 为 `mock`、`real` 或 `unavailable`；`reason_code` 可为 `missing_api_key`、`invalid_provider`、`invalid_configuration`，`message` 为静态安全说明。`ready` 只说明本地配置校验通过，不代表已连接远端、认证有效、额度充足或真实图像质量已验证；启动和状态读取不应为了显示“可用”而发起生成请求。

| 状态 | 用户应看到的事实 | 操作行为 |
| --- | --- | --- |
| 默认模拟模式 | “模拟图像服务”，程序 SVG、非 AI 生成、不消耗模型额度 | 正常创建和失败重试，保留现有完整流程 |
| 外部模式、配置就绪 | 选定服务与模型；说明本地配置就绪，实际请求可能失败 | 可提交；按钮不能继续写“创建模拟图像”或“不消耗额度” |
| 外部模式、配置不可用 | 安全明确的不可用原因及由服务端配置的提示 | 新任务/重试提交禁用；后端对新请求返回 503 `provider_not_ready`；仍可读取旧任务、结果和已保存素材 |
| 能力接口读取失败/加载中 | “正在读取服务状态”或明确失败，并可重新读取 | 未确认模式前不假定为 mock 可用；不提交新的生成任务 |
| 已接受任务、执行中 | 真实队列阶段与实际任务来源 | 202 仅表示接受任务，不能当作图像成功；不暗示真实完成百分比 |
| 外部任务失败 | 安全、可理解的错误；原记录保留 | 不生成模拟替代图，不伪造成功；按冻结重试规则处理 |

外部请求和结果处理链为：后端校验与持久化新任务 → worker/Eino 调用选定适配器 → 有界 HTTP 请求 → 校验返回图片 → 安全写入本地文件 → 持久化成功状态与结果引用 → 浏览器经原结果 API 展示 → 保存到素材库并可检索。保存素材只是将成功结果加入素材库，不能再次调用图像服务。

页面全局提示描述“当前新任务使用的服务”；任务卡、详情、图片替代文本和素材标识描述该条记录实际保存的来源。即使当前切换为外部模式，历史 mock 仍须标明“模拟图像 · 非 AI 生成”；外部结果不能继续冠以 MOCK SVG。开发验证中的外部协议图片来自本地假服务，展示和交付说明不得将它们宣称为已经调用官方模型生成的样例。

浏览器保留旧页面、服务端重启切换模式时，新请求不能在仍显示 mock/免费文案的情况下被真实服务接受。提交所依据的服务身份需要与用户看到的 provider/model 一致；不一致时更新提示并停止这次新建，由用户根据新模式再次明确提交。已接受请求的原键重放仍用于确认原记录，不能因配置变化而改为新模型执行。

冻结的实现约束为：前端普通创建与重试成对传入 `expected_provider`、`expected_model`，mock 对应 `mock-svg` 与空字符串，外部模式对应 `openai-images` 与固定 snapshot。这两项只保护本次提交的模式预期，不属于创作输入、持久化任务字段或幂等身份。后端先返回正确的已接受幂等重放，再对新请求检查就绪状态及模式预期；未就绪返回 503，已就绪但预期不匹配返回 409 `provider_changed`，不得产生新任务或网络调用。前端收到模式变化后刷新能力、显示提示，等用户再次点击，不自动改模式重发。旧 API 客户端两项均省略仍兼容，调用者自行负责其模式确认。

## 结果、历史与错误语义

Task 和 Asset 固化 `provider` 及适用的 `model`；新成功结果返回 `result_mime`、`result_width`、`result_height`，历史 SVG 可缺少尺寸。Task 的失败分类另有 `error_code`，内部保留必要的本地文件引用；素材继承来源任务的身份与结果元数据。接口不能泄露密钥、本地绝对路径、原始 Authorization、上游未筛选的错误正文或测试服务内部信息。

外部响应只接受本轮约定的 base64 PNG，JSON 响应上限 24 MiB，解码 PNG 上限 16 MiB。必须检查解码、格式、精确尺寸和大小约束；空数据、损坏数据、非图片、外部 SVG、仅 URL 响应、尺寸不符和过大内容不能成为成功结果。本轮不下载上游返回的任意 URL。文件在服务管理的数据目录内以服务端生成的引用落盘，不允许客户端、提示词或上游数据决定文件路径。

图像成功写入并与任务记录关联后才能发布成功状态。重启后读取到相同结果，旧 SVG 和素材仍可读；结果文件缺失或存储失败应报告实际错误，不静默生成占位图，也不删除历史以恢复启动。结果读取继续执行现有空间归属检查，但不宣称生产权限隔离。

现有客户端提交幂等继续有效，同一次超时或丢响应后重发不会额外创建任务。已接受请求的正确同键重放先返回原记录，不受当前模式不可用影响；只有真正需要新建执行的请求才受就绪状态限制。远端调用不做自动生成重试；429、5xx、超时或断连都不能触发无提示的再次生成。外部任务在调用期间进程中断，重启后变为 `failed` / `execution_interrupted`，不能沿用 mock 的“重启即重新生成”策略；用户须看到中断、远端可能已经执行以及未自动重发的说明。用户显式重试是新的执行尝试，原任务与关联须保留，可能再次产生服务费用，不能承诺上游 exactly-once。

API 支持不可用配置下的旧请求重放，不代表界面在能力未知时继续发 POST。本轮界面在能力未知或 `ready=false` 时一律暂停提交，保留尚未确认尝试的原 key 和草稿，待能力恢复后再用原 key 确认；不提供绕过能力状态的“确认上次提交”例外。

服务配置改变后，旧任务不得被另一种 provider 或模型悄悄执行。queued 任务固化的 provider/model 与当前 active 配置不匹配时，标为 `failed` / `provider_unavailable`，不发起网络请求。已完成结果按自身来源继续读取。显式新重试绑定当前 provider/model，界面在提交前说明当前服务与可能再次计费；不能把模式切换伪装成原调用的恢复。mock 的已有恢复行为继续回归验证。

## 可测试验收标准

所有运行证据由独立测试记录提供。外部协议验证必须经过真实 HTTP 边界和实际文件存储，仅替换函数返回值的单元测试不能代替联调。测试通过构造器注入本地 HTTP 假服务，使用随机回环端口、独立临时目录及非真实凭据的测试占位值，不调用官方生成端点。运行配置固定官方 endpoint，不为测试新增任意远端 URL 的生产配置入口。

## 本轮证据边界

本轮已完成产品范围定义、官方协议资料核对、布局证据边界记录和修复后的代码复核；运行验收以独立验证记录为准。用户 Library 截图没有成功读取，布局修复范围以仓库截图独立复现为依据。真实图像协议适配器的实现与本地假服务通过，只能证明请求、解析、存储和界面链路；官方服务的实际认证、生成质量、可用性与费用均未验证。本轮不新增或获取真实凭据，不进行付费调用。

本次复核反馈已在代码中关闭：

1. 旧页面模式保护：前端创建/重试携带当前能力的 expected 对，`createLocked` 在仓库锁内先处理旧幂等记录，再验证就绪与预期模式。旧页面向不同模式新建时返回 `provider_changed`，不创建任务。前端仅刷新能力并提示用户再次点击，不自动重发，不清除草稿或原 key；能力未知/不可用时不再提供特殊 POST 入口。已复读 `App`、`useWorkspace`、HTTP 解码与仓库分支确认这一代码路径。
2. 结果不确定文案：`TaskDetail` 的失败占位已改为“本地暂无可用结果”，同时保留具体 `error`、`error_code` 和在重试编辑时呈现的费用不确定提示，不再推断远端一定没有生成。

产品代码复核无剩余待办，文档冻结。上述关闭结论仅来自代码复读，不代替 QA 对模式切换、幂等、实际 HTTP/存储、布局和浏览器交互的运行验证。
