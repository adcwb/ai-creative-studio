# 第六轮产品范围与验收

基于已发布 `2ff0b9260471d3ac6b248ee8ce07e16b4cdf9447`。用户授权同时推进真实 AI 创作接入和短剧成片链路，不以单接口或规划完成代替交付。本轮仅本地实现、验证和提交，不推送、不部署、不配置凭据、不调用付费模型。用户追加要求可替换适配器兼容 OpenAI、Claude、Gemini、字节、MiniMax、即梦与 Nano Banana 相关生态。必须区分厂商、模型和消费产品，只接官方 API，模型 ID 可配置，能力矩阵明确未支持或需授权项目；具体模型、账号和预算尚未提供。

## 依赖里程碑

| 阶段 | 用户可验收结果 | 完成依据 |
| --- | --- | --- |
| 1. 媒体与供应商基础 | 有明确来源、类型、项目归属的媒体资产；安全上传、请求限额、版本检查和持久幂等 | 实现、故障测试、准确API契约 |
| 2. 创作适配 | 需求分析与澄清、结构化剧本与分镜，以及图像、视频、语音的真实协议适配；默认模拟仍清楚标注 | 本地模拟上游覆盖正常、无效响应、超时与中断；不代表真实模型验证 |
| 3. 可编辑资产与创作过程 | 角色参考素材、照片上传与编辑、逐镜资产关联、镜头增删排序、剧本及分镜历史回滚、可编辑时间轴 | 刷新后可读、并发冲突不覆盖、旧稿与资产来源可追溯 |
| 4. 本地成片与完整回归 | 图片或视频、配音、音乐/音效、字幕按时间轴真实合成，预览并导出 | 实际生成MP4，媒体探测与浏览器播放，桌面/手机全流程与原图像/剧本/分镜回归 |

每阶段完成后继续下一阶段。某一步需要供应商、权限或预算时明确标为待验证，继续独立工作；不将该依赖扩大为所有实现的阻塞。

## 验收场景

1. 用户从已保存需求发起分析，区分模拟建议和真实协议配置，看到需要澄清的信息；未保存编辑不能被伪称为已使用的生成来源。
2. 剧本与分镜保留结构校验、异步状态、来源版本、失败保留旧稿与冲突保护。真实外部执行不因重启或网络错误自动重新发送；结果不明可能已计费。
3. 用户上传有界格式素材，看到项目归属与素材来源；非法格式、超限文件、任意外部URL、跨项目素材不能进入合成。角色参考是创作约束或输入素材，不能承诺跨镜头身份一致。
4. 分镜镜头可增加、删除和调整顺序；保存使用版本和幂等检查。历史恢复产生新的当前版本，保留原记录，不能静默覆盖新编辑。
5. 用户将图片或视频与镜头关联，在时间轴调整顺序、时长、字幕和音频，保存后刷新仍存在。合成以已保存时间轴为准。
6. 用户发起合成，看到状态、失败与取消；重复提交回到同一操作，不创建重复导出。导出可预览和下载；内容明确标明合成演示或其真实来源。
7. 测试使用合成素材和本地假上游；媒体探测证实容器、视频时长、音轨和字幕，浏览器验证实际可播放。真实模型质量、供应商认证、可用性与费用均保持未验证。
8. 桌面、手机、长内容及旧流程继续使用映创深绿/暖白品牌；错误、空状态和未配置状态可区分，不出现仅装饰的功能按钮。

## MVP 边界

本轮不是专业非线性剪辑软件或企业账户计费系统。演示空间没有身份认证，不是租户权限边界；本地服务不能直接公开部署。必要的上传校验、媒体资源限额、外部URL防护、幂等、版本冲突与避免自动重复收费属于本轮范围。账户、预算和真实供应商测试是独立授权事项。

最终实现范围、已执行检查与未完成项以 [第六轮验证](iteration-6-verification.md) 为准；接口以 [OpenAPI](../api/openapi.json) 和 [第六轮架构](iteration-6-architecture.md) 为准。本文定义验收目标，不把尚未通过的项目写为已完成。

## 原生文本协议依据

Anthropic 采用明确锁定的 `2023-06-01` Messages 协议；Google 采用 `generateContent`。模型 ID 由配置提供，不能把厂商生态名称或消费产品名称直接当作可调用模型。仅实现结构化需求分析、剧本与分镜文本；这两个文本适配器不会把语音/视频请求路由到文本 API，而是明确返回能力不支持。没有默认模型、真实密钥或真实模型效果验证。

官方依据（2026-10-23 查阅）：[Anthropic Messages](https://platform.claude.com/docs/en/api/messages)、[API 版本](https://platform.claude.com/docs/en/api/versioning)、[认证](https://platform.claude.com/docs/en/manage-claude/authentication)、[Gemini generateContent](https://ai.google.dev/api/generate-content)、[Gemini 结构化输出](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)。本地协议验证不证明任意未来模型与所选 API 版本兼容；模型权限和能力仍需操作者核对。

MiniMax 文本采用其[官方 OpenAI 兼容接口](https://platform.minimax.io/docs/api-reference/text-openai-api)，单独处理推理内容分离和输出长度参数，不把兼容接口当作所有 OpenAI 参数均受支持。该文本适配器不复用文本接口生成媒体；MiniMax 语音已通过独立原生 T2A 协议实现，MiniMax 图像与视频通过独立官方媒体协议实现。

## 角色参考与图像模型边界

OpenAI、Gemini、方舟与 MiniMax 图像适配提供可选 `reference_asset_id`，将已有参考图片作为图像输入。角色选择用于资产关联；需要的角色描述由用户写入创作提示。它能传递外观约束，不能保证跨镜头身份或细节一致；没有锁脸、角色微调或一致性质量评测承诺。Google/Nano Banana 图像有独立 `generateContent` 和 Interactions 适配，须按具体模型选择协议；不能以一个协议覆盖所有型号。方舟视频适配与 OpenAI 视频为不同协议，各自的模型权限和真实效果仍未验证。

## 即梦公开图像协议

即梦图像使用公开火山视觉 API 的 AK/SK 签名，不调用消费网站或逆向接口。`req_key` 显式配置；提交强制单图，随后只查询同一任务。签名根据[官方 Go SDK](https://github.com/volcengine/volc-sdk-golang/blob/64e6e051a12441821178c93b8922db4e7158d3e1/base/sign.go)核对，并以该 SDK 独立计算的固定合成凭据向量验证。请求/状态依据[即梦图像4.6官方接口](https://docs.volcengine.com/docs/JimengAI/JimengAI-ImageGeneration46-InterfaceDocumentation?lang=zh)。

只接受 `code=10000` 且任务完成后的内联图片；仅返回 URL 时安全失败，不下载任意外部链接。此适配为文生图，不提供即梦参考图编辑或视频：4.6文档仅支持URL参考，需要公网素材桥接，当前没有此项授权；旧视频接口下线，不虚构可用能力。提交不自动重试；上游任务ID已纳入持久记录，图像任务和项目创作任务可显式恢复查询原任务，不重新提交。未拿到或未成功持久保存上游ID时仍不能保证恢复，远端执行和费用可能不确定。签名与本地假上游通过不等于真实账号、模型权限或效果验证。

## 实现覆盖与后续工作

逐供应商逐模态能力及配置项集中在 [README](../README.md#已实现的供应商能力)。文本与图片理解覆盖 OpenAI/Anthropic/Gemini/方舟/MiniMax；图像覆盖 OpenAI/Gemini/方舟/即梦/MiniMax；参考图覆盖除即梦以外四家；视频覆盖 OpenAI/Google Interactions/方舟/MiniMax（方舟和MiniMax支持首帧）；语音覆盖 OpenAI/Google Interactions/MiniMax/独立豆包TTS。供应商有此能力不代表任何配置模型都支持，服务端能力状态不等于真实认证成功。

- 照片编辑仅浏览器旋转/居中正方形裁剪，生成新素材保留原图；不是通用AI图像编辑器。
- 角色描述和参考图片是尽力约束，无法保证跨镜头身份或细节一致；MiniMax是人物参考，不提供mask编辑。
- 时间轴支持逐句cue与起止时间；文本估算不识别音频，OpenAI ASR是待人工复核的转写候选，用户应用后仍需保存。ASR只接显式whisper-1时间戳协议，默认不可用；其他ASR模型未接入。此实现不是词级强制对齐或口型同步。
- 音乐/音效支持上传、选用与混音，不包含真实生成式音乐模型；配音API未配置时不以正弦音冒充真人语音。
- 即梦参考图需公网URL桥接，本轮未创建或授权；旧视频接口下线，未假造可调用模型。Google视频只接文生视频，不含首帧/视频编辑。专业多轨剪辑、自动身份质量评测及通用mask编辑未实现。
- 提交绑定provider/model；媒体回执精确关联资产。视频及即梦图像可按持久上游ID显式恢复原任务查询，不重复生成。取消本地等待不保证远端取消或停止计费。

真实认证、用户选定模型、质量、一致性与实际费用均待验证；当前无凭据或付费调用。最终完整QA见[追加验证记录](iteration-6-followup-verification.md)，原[验证记录](iteration-6-verification.md)保存第一阶段快照，不将早期48项E2E或局部协议测试当作追加实现最终全通过。

## MiniMax 媒体协议补齐

图像使用[官方原生图像API](https://platform.minimax.io/docs/api-reference/image-generation-i2i)，强制单张、内联base64和业务成功码校验；参考输入为单个 `subject_reference` 人物图，不是mask/inpainting工具。图像的4:5比例只在支持显式宽高的 `image-01` 模型使用1024×1280；其他模型拒绝该比例，不静默替换。

视频使用官方[创建](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)、[查询](https://platform.minimax.io/docs/api-reference/video-generation-v2-query)和[取消](https://platform.minimax.io/docs/api-reference/video-generation-v2-delete)协议，固定5秒/768P，可提交首帧；任务ID交由统一队列持久保存。结果下载复用HTTPS、公网IP检查、DNS固定连接、无凭据/代理/重定向的受限下载器，并校验MP4格式。适配器的远端取消只在查询显示queued时尝试，running不允许取消；终态DELETE是删除记录，不能当作成功取消。查询与DELETE间仍有上游状态变化窗口，故默认本地停止语义与远端取消必须明确区分，不能保证免费或停止计费。

本地假上游仅验证请求结构、状态与安全错误处理；实际模型、账号权限、输出质量和费用仍未验证。
