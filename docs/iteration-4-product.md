# 映创第四轮产品范围与验收标准

基线为 `7dab4ea655d51f1edac123c33053c6d26a750a28`。本轮只进行本地实现、验证和提交，不推送、不创建 PR、不部署。本文先定义产品要求；功能完成与运行通过须有后续审查和独立测试证据。

## 目标与范围

路线依据是 [总体架构](architecture.md) 的“后续适配路径”：项目 → 创意分析 → 剧本 → 分镜 → 角色一致性资产 → 音视频生成 → 合成。本轮只实现首段的一个完整流程：在演示空间内创建短剧项目、保存创作需求、异步生成结构化模拟剧本、编辑并保存当前剧本。

所有可操作功能都必须通过真实后端 API 执行校验、业务逻辑和持久化，生成经过实际编译、调用的 Eino 流程。`mock-script` 是程序生成文本的模拟 provider，不是调用真实语言模型；界面展示的项目、状态和剧本必须来自后端，不能用前端固定样例、延时假成功或浏览器内状态替代业务实现。

本轮只处理单集、两名角色、三场戏。保留一份当前剧本和持久化生成记录，不提供多集、可浏览的剧本版本历史、项目删除、角色库、分镜、音频、视频、合成或导出。没有真实文本模型配置、密钥入口或外部付费文本调用；不宣称已经完成创意分析模型或验证了剧本创作质量。

原有图像工作台、素材库、真实图像协议适配器、模式保护、错误语义和布局继续保留。短剧始终使用独立的 `mock-script`，不受图像 provider 配置影响；图像服务缺少密钥或不可用时，不能阻断短剧流程，也不能让短剧请求触发真实图像生成。沿用映创品牌和现有设计风格。

## 用户路径

1. 从工作台导航进入“短剧创作”，看到当前演示空间的真实项目列表及明确的模拟文本说明。首次进入显示空状态和新建入口，不预置已经生成的样例项目。
2. 填写项目名称与创作需求，提交创建。API 成功并持久化后才将项目呈现为已创建；错误时保留输入。项目名称与剧本标题分开呈现，避免用户误以为修改一个会自动修改另一个。
3. 查看或修改项目需求并明确保存。有未保存修改时，生成入口提示先保存或取消；生成取后端已保存的需求快照。后端接受后显示排队或执行状态，直到实际生成结束。202 不代表剧本已经成功。
4. 成功后读取两名角色、三场戏的结构化剧本。角色设定与对白角色归属只读；用户可编辑剧本标题、梗概、每场标题、动作描述和已有对白文本，再明确保存。没有增删角色、场次或对白行的界面操作。
5. 再次生成已有剧本前，明确告知“成功后替换当前已保存剧本，失败保留原稿”，由用户确认后提交。生成中保留旧稿供阅读，暂时锁定本项目内容编辑与新的生成；其他项目仍可使用。
6. 生成失败显示真实错误和失败状态，已保存旧稿不变。用户可修改需求、保存后再发起新的生成尝试；不自动删除测试故障标记，也不把失败记录改成成功。新尝试与重试结果尚未确认的同一次请求使用不同的幂等语义。
7. 页面刷新或服务重启后，从 API 恢复已保存项目、版本、剧本、来源需求和生成状态。未提交的输入是本地草稿，不显示为已保存；取消编辑恢复当前已读取的保存内容，不发起内容写入，也不取消已接受的生成。

切换项目、工作台或演示空间时，有未保存编辑须明确确认弃稿或阻止切换；页面刷新/离开也应提示未保存内容。读取、保存或生成失败不能悄悄清空草稿。版本冲突保留用户编辑并提示重新读取，重载前说明草稿会被放弃；不自动以本地旧内容覆盖服务端较新版本。空间或项目切换后的迟到响应不能填入另一个项目。

## 数据与校验边界

所有长度按去除首尾空白后的 Unicode 字符计算，前端提示不能代替后端校验。完整字段类型、错误码和接口结构以 [第四轮架构](iteration-4-architecture.md) 与 [OpenAPI](../api/openapi.json) 为准。

| 数据 | 本轮约束 | 用户行为 |
| --- | --- | --- |
| 项目 `title` | 1–80 字符 | 新建、编辑保存 |
| 项目 `brief` | 3–2000 字符 | 新建、编辑保存；生成取保存后的快照 |
| 剧本 `title` | 1–80 字符 | 编辑保存，与项目名称独立 |
| 剧本 `logline` | 3–300 字符 | 编辑保存 |
| `characters` | 恰好 2 名；`name` 1–40、`description` 1–200 字符；角色可明确区分 | 本轮界面只读，保存时仍校验完整结构 |
| `scenes` | 恰好 3 场；`heading` 1–100、`action` 1–1000 字符 | 编辑已有场次内容，不增删场次 |
| 每场 `dialogue` | 1–6 句；`text` 1–300 字符；`character` 必须引用该剧本有效角色 | 编辑已有对白文本，角色归属只读 |
| `version` | 服务端版本，随项目内容成功保存或生成成功递增 | 修改和生成携带 `expected_version`，不由前端猜测更新 |
| `script_brief` | 当前剧本对应的生成需求快照 | 与当前需求不同则提示“当前剧本来自此前需求”，不能自动改标为已更新 |

空白、超长、错误类型、非法结构和无效角色引用都应由 API 拒绝，并且没有持久化副作用。保存不成功时不能显示成功提示或提前推进版本。完整剧本保存使用服务端结构校验，不能将任意 JSON 当作成功剧本存储。

角色设定、对白归属及行结构的“只读”仅指本轮界面编辑器未提供这些操作，不是 API 字段权限承诺。`PUT /projects/{id}/script` 接收完整 Script，也允许满足数量、长度、角色唯一性和引用约束的合法修改。`script_brief` 则是真正的服务端来源元数据，保存请求不能提供它；手工编辑剧本不会改写该来源。

## 后端闭环与状态

范围内接口均在 `/api/v1` 下，并携带现有演示空间作用域：`GET/POST /projects`、`GET/PUT /projects/{id}`、`GET/POST /projects/{id}/generations`、`PUT /projects/{id}/script`。项目列表、详情、生成列表及编辑器的数据来自这些真实接口。跨空间读取或写入不能借已知项目 ID 绕过现有归属过滤；这仍只是公开演示空间的数据归属，不构成生产认证或企业隔离。

创建项目首次成功返回 201；生成首次接受返回 202；内容保存及正确幂等重放返回 200。所有写操作携带幂等键，修改与生成同时携带预期版本。幂等记录真实持久化：同一次已接受请求的正确重放不再应用原写入；同键修改输入、混用操作或目标应冲突。创建与内容保存的重放返回当前项目投影，生成重放返回原尝试当前状态，不将历史响应误当作最新内容。

响应丢失或结果不明时，前端保留原 body、预期版本和原键，入口称为“重试同一请求”，不能宣称是只读查询或仅确认状态：若此前已接受，返回该操作的当前结果；若此前未接受，这次可能首次执行。已接受的请求不会因此额外创建项目或生成。用户明确开始新的生成尝试才使用新键；不能在结果不明时自动换键或修改 body 重发。本轮固定 mock-script，没有因此产生付费文本调用。

生成持久化项目、需求和版本的输入快照以及 `queued/running/succeeded/failed` 状态，并明确记录 `mock-script` 来源。Eino 流程校验输入、执行模拟生成并校验输出；生成内容应使用该项目的已保存需求，不能把同一份前端示例当作不同项目的结果。模拟文本只能证明流程与结构，不能证明真实模型理解或创作能力。

同一项目在 queued/running 时，后端原子拒绝编辑与第二次新生成，而不只依赖禁用按钮；版本检查也在后端执行。生成成功时，剧本、来源需求、项目版本和生成终态一致持久化后才发布成功。生成失败不覆盖原稿、不推进内容版本；读取失败或写盘失败不发布伪成功。明确的 `[mock-fail]` 需求可用于验证失败路径，保留故障原输入供用户检查。

模拟生成执行中进程中断后，恢复规则为重新排队并继续执行；属于至少一次执行，不宣称 exactly-once。已完成的保存、版本和幂等记录重启后仍在。扩展现有文件存储须兼容旧图像数据，不能清空原有任务、素材或结果以完成升级；本轮不引入数据库迁移或生产基础设施。
