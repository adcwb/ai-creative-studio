# 第八轮 PostgreSQL 持久化与离线迁移

本轮 PostgreSQL 后端实际读写业务、身份、费用和模型配置数据，不是部署容器占位，也不是把整个应用 JSON 文件写入单一数据库字段。数据库仍应由部署方配置、授权和备份；没有创建正式账号、云数据库或生产凭据。

## 实现范围

- `studio_image_tasks/assets`、`studio_projects`、`studio_script_generations`、`studio_storyboard_generations`、幂等收据和历史分别持久化记录；`studio_users/organizations/sessions`持久化身份与会话；预算限额、费用条目和预算变更分别持久化记录；创作任务、字幕对齐、媒体项目、租户模型配置也有各自表。
- 每条记录带 `tenant_id/entity_id/version/state` 等关系列和可变内容 JSONB。图像素材关联任务、剧本/分镜/创作/对齐关联项目使用同租户复合外键；会话/组织所有者关联用户。预算使用 bigint 最小单位、显式币种和约束；不执行静默兑换。
- 现阶段媒体资产/导出仍在“每媒体项目记录”中，模型配置仍在“每租户版本记录”中；不是所有子对象都拆成独立表。组织成员保存在组织记录中，由服务端 RBAC 校验，尚未开启 PostgreSQL RLS。不要把数据库连接分发给不受信任的客户端。
- 原领域层仍使用 `FileStore` 类型名以保持路由和行为兼容；PostgreSQL 模式不写本地领域快照。每次领域锁都开启 SQL 事务并刷新数据库记录，禁止用旧内存记录授权。刷新失败清空本地缓存、拒绝写入，并递增持久化失败计数供 HTTP 边界返回 503。
- 会话、成员权限、模型配置从数据库刷新。OIDC state 的绑定检查与删除使用一个 `DELETE ... RETURNING`，重复回调不能跨实例重放；登录失败限流共享且只存地址摘要。模型执行的跨实例撤销检查由运行时保护实现。
- 领域修改与版本检查在同一事务；图像/剧本/分镜接受任务时，同时写业务记录、持久队列和用户明确同意的币种上限预留。执行阶段报价不得超过该预留；未知费用继续占用。其他任务接线详见本轮执行/队列说明。
- 队列使用 PostgreSQL 本身，避免 PostgreSQL/Redis 双写；租约完成时同事务检查执行凭证。结果对象写入前也检查租约，提交时再次检查。过期已发送任务保留 unknown，协调器把对应领域状态标为 `execution_outcome_unknown`，不重发。

## 配置与边界

运行时需要显式 PostgreSQL 连接配置及已初始化 schema；默认文件模式不隐式切换。`InitPostgres` 是显式迁移操作，常规应用账号不应持有 DDL 权限。连接字符串可能含敏感值，不能放进公开报告、日志或命令历史。正式部署需要 TLS 和独立最小权限账号，本轮仅在合成、本地 Unix socket 数据库验证。

为了安全复用现有领域逻辑，目前每领域使用一条数据库 scope 行串行化读取和写入，并在锁内加载该领域全部记录。这能保证当前多实例一致性，但不是高吞吐设计：不同租户在同领域会争用锁，记录规模增加会增加延迟和内存。后续需要按租户/实体细化事务、分页及索引查询。真实两实例测试不代表已验证任意生产容量。

`DATA_DIR` 在 PostgreSQL 模式只用作私有媒体缓存/临时工作目录。两个进程应有不同缓存目录并共享同一受控对象后端，不能把各自本地文件当作多实例共享存储。发现旧领域快照时拒绝启动，防止不明确的数据来源优先级。

## 停服迁移与回滚

1. 停止全部 API 与 worker，备份完整原目录及对象数据，单独保管加密主密钥。源目录必须含有效 `state.json`，不能把缺失元数据当作空库。
2. 显式初始化空 PostgreSQL schema。执行 `store-migrate` 的 import 操作：获取源文件锁，拒绝符号链接/非普通文件，对有界元数据做隔离副本验证，然后在一个 SQL 事务中导入领域记录、幂等身份、审计和对象 manifest。非空目标拒绝导入。
3. 中断的旧单进程任务按原恢复规则处理；没有账单证据的预留转为 unknown，不释放。旧演示租户不会被自动分配给新账户。源目录不被改写。
4. 按迁移报告记录数、SHA256 和对象 manifest 检查；使用对象迁移工具复制并验证二进制媒体。元数据 import/export 都明确返回 `requires_media_copy=true`，不能把元数据转换当作完整媒体恢复。
5. 用新的空缓存目录启动并验证，然后才允许新写入。没有双写协议，不能在有新数据后直接指回旧目录宣称无损回滚。
6. 回滚时再次停止全部进程，export 到一个不存在的新目录，恢复匹配的媒体文件或经验证的 S3 配置与主密钥。导出不会覆盖现有目录；文件及目录同步后使用不可替换 rename。OIDC 未完成授权不迁回文件模式，应重新开始登录。

迁移的数据库 advisory barrier 会协调应用领域写入，但**停服仍是操作前提**，不能把它当作线上无停机迁移。普通数据库管理员仍可直接修改表；审计不是外部不可篡改档案。

## 已执行的真实验证

使用隔离的官方 PostgreSQL 17.11 本地进程、随机 schema 和合成数据：

- 两个实例竞争同幂等请求，20 次请求只有一个业务任务和一个队列任务；跨租户查询/关联拒绝。
- 两实例预算竞争：限额 100、每次预留 30，20 次并发只有 3 次成功；超额接受事务不遗留任务/队列；取消只释放未发送 reserved。
- 会话删除、成员撤销和模型凭据撤销不能被旧缓存复活；OIDC 同 state 一次消费和跨实例限流。
- 每个测试 schema 都建立外键，不因另一个 schema 同名约束而跳过；数据库读取失败不返回缓存数据，并能通知 HTTP 错误边界。
- 文件→空数据库→新目录往返，任务 ID/幂等和 unknown 费用保留，活动源/缺失核心状态/符号链接/非空目标/覆盖导出拒绝。
- 实际 `pg_dump` 自定义格式备份，再 `pg_restore` 到全新合成数据库，逐域元数据比对一致，并检查任务幂等及 unknown 费用状态。

这些测试使用显式 `STUDIO_POSTGRES_TEST_DSN`；native restore 另需 `STUDIO_POSTGRES_BIN_DIR` 与可选 `STUDIO_POSTGRES_LIB_DIR`。变量缺失会明确 skip，不能把 skip 算成实际集成通过。没有执行真实供应商调用，也没有创建正式服务器资源。

## 离线费用对账

`budget` CLI 显式区分文件和 PostgreSQL 后端。PostgreSQL 模式要求 `STORAGE_BACKEND=postgres`、已安全注入的 `DATABASE_URL` 和 `--confirm-stopped`，不会在缓存目录创建一个假的本地账本。文件模式要求现有 `state.json`，不能误用 PostgreSQL 缓存目录。

停止全部 API/worker 后可使用 `--action report|limit|reserve|unknown|settle|release`、`--tenant`、`--currency`、`--id`、`--amount-minor` 和 `--evidence-ref`。settle/release 必须有非敏感账单证据引用；跨币种/跨租户拒绝，unknown 不会因进程重启自动释放。此工具不调用供应商、不抓取真实账单、不自动充值，操作员须自行核实证据。

维护工具使用数据库维护锁协调领域事务，并把开始/结束写入审计；**这不是自动停服或全数据库冻结**，队列 Claim/Dispatch/Renew 等操作不依靠该锁。因此 `--confirm-stopped` 表示操作员已停止全部进程，不能拿该参数替代实际停服。数据库管理员权限本身就是离线管理边界，不等于网页组织管理员权限。
