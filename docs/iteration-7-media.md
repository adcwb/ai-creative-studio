# 第七轮：有界媒体编辑与导出

本阶段不调用外部模型。所有输出检查使用合成色块、正弦音和文本，证明本地编码链路，不证明模型质量。

## 实现与接口

沿用 `PUT /api/v1/projects/{id}/media/timeline` 的版本与幂等协议，导出冻结完整时间轴快照。新增字段均可省略，旧数据保持原行为。

| 对象/字段 | 范围与缺省 |
| --- | --- |
| timeline.output_resolution | `360p`（缺省640×360）、`720p`（1280×720）、`1080p`（1920×1080） |
| timeline.aspect_ratio | `16:9`（缺省）、`9:16`（交换宽高）、`1:1`（短边方形） |
| timeline.subtitle_mode | `soft`（缺省MP4字幕轨）、`burn`（真正烧录画面）、`none`（MP4无字幕；仍生成SRT/VTT供下载） |
| timeline.audio_tracks | 最多8条附加音轨；每条 `{id,asset_id,start,trim_start,duration,volume}`，位置相对全片，素材须属于同项目且为音频；音量0–1，时长至少0.1秒，不超素材/成片范围 |
| clip.preserve_source_audio | 默认false；true时保留视频源音轨并与配音混合，无源音轨的视频自然保持静音 |
| clip.source_audio_volume | 0–1；缺省0，保留原音时须明确选择音量 |
| clip.transition | 缺省无转场，`fade`使本镜头淡入/淡出黑场；不是重叠交叉溶解 |
| clip.transition_duration | fade每端时长0.1–2秒且最多镜头一半；不改变总时长或字幕位置 |

混音顺序：视频原音与本镜配音混合 → 按原时间轴顺序拼接 → 循环背景音乐及定位附加音轨混合。混合使用不自动归一化的加法与限幅器（0.95，补偿延迟），不会静默降低用户选定各轨相对音量；强信号可能触发限幅，需试听。附加音轨不自动循环，入点裁剪后按 start 延迟；原有背景音乐继续循环。

字幕烧录使用 FFmpeg libass，最终容器无需字幕解码即可显示；Docker原有FFmpeg及中文字体保留。选择 `none` 时网页若显式加载独立VTT仍可显示外挂字幕，它不属于MP4画面。淡入淡出作用于视频，未自动修改声音包络；附加音轨仍可精确设起点和音量。本实现不提供专业多层视频合成、交叉溶解或自动音量均衡。

## 资源与兼容

固定24fps，H.264/AAC；360p最多180秒，720p最多120秒，1080p最多60秒。原1–30镜/单镜0.5–30秒/同时2个导出/5分钟编码超时继续生效。按清晰度使用4/6/8Mbps视频峰值码率约束（VBV 16Mb），每个活动导出保守预留256MiB临时/输出空间；单个完成MP4超过128MiB时导出失败，不发布截断文件。所有数值需有限，拒绝未知比例、清晰度、字幕/转场模式及跨项目音轨。

媒体快照版本保持1，新字段使用可选JSON，无破坏式迁移。上线前停服备份完整 `DATA_DIR`；回退旧二进制需恢复匹配备份。旧版本读写可能丢失新增编辑字段，不应以旧二进制编辑新时间轴。原素材及已完成MP4不覆盖；失败导出保留旧产物。部署/发布仍需父任务统一处理。

## 测试

`TestEnhancedTimelineValidation` 覆盖输入、数值、工作量与音轨归属限制。`TestEnhancedMediaActualEncoding` 实际编码720×1280烧录、1920×1080软字幕、360×360软字幕；ffprobe检查尺寸与流，解码RGB检查烧录文字和黑场淡入，解码PCM检查附加音轨尚未开始时原视频音轨可听。最终全量结果由统一验证记录汇总。
