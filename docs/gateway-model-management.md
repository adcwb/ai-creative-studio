# AI 网关与功能模型管理

模型管理位于系统设置的“组织运行配置”，也可从 `/settings/models` 进入，分为“功能绑定”“AI 网关”“网关模型”三个页签。一个组织可以配置多个网关，每个网关可以配置多个模型。不同网关允许使用相同的上游模型名称，后台通过独立 ID 区分。

## 配置顺序

1. 在“AI 网关”添加名称、完整 Base URL 和请求超时。Base URL 包含实际 API 前缀，例如 `https://gateway.example.com/v1`；只有根地址时自动补 `/v1`，已有前缀不重复添加。
2. 部署方配置凭据加密密钥后，新建网关直接输入 API Key；编辑已有网关时选择“设置 API Key”。所有模型共用该网关的加密凭据。更换服务地址须重新设置密钥，页面和接口均不返回明文。
3. 在“网关模型”选择所属网关，填写网关实际接受的模型 ID，例如 `vendor/model-alias`，再选择已确认的能力。一个模型可以同时具有文本和视觉等多种能力。
4. 为模型设置最大输出、JSON 输出模式、视频参数及单次费用上限。上限为原币种最小单位的整数，界面按币种精度录入金额；来源说明不能为空才能生成报价。这是管理员设置的保守预留上限，并非供应商实际账单。
5. 在“功能绑定”逐行选择网关、模型，保存剧本、分镜、角色图、镜头图、视频或语音等功能的绑定。模型列表仅展示该网关下满足功能能力要求的条目。更换网关立即清空旧模型。
6. 创作入口默认选中功能绑定。允许本次切换时，用户可以临时选择其他满足要求的模型；关闭此选项后，服务端也会拒绝覆盖。用户获取并确认当前请求费用上限后提交真实生成。

分镜规划使用文本推理模型；镜头图片和镜头视频分别使用图像、视频模型。普通语音转写和需要时间戳的字幕识别分别配置，网关需实现对应 JSON／verbose JSON 协议。能力声明并不证明模型权限或质量，需通过真实小样核对。

旧供应商编辑页面已移除，旧 PUT 接口返回 410；历史配置／凭据不会被删除，保留读取、执行兼容与管理员显式撤销。新维护统一使用网关，不自动转换原生协议。详见 [配置迁移](settings-configuration.md)。

## 支持的网关操作

| 能力 | 兼容协议 |
| --- | --- |
| 文本／分镜 | `POST /chat/completions`，结构化 JSON 内容，最大请求 64 KiB、输出最多 6000 token |
| 图片理解 | Chat Completions 图片输入及 JSON 内容输出 |
| 图像生成 | `POST /images/generations`，单张 base64 或受控公开 URL 结果 |
| 图片编辑 | `POST /images/edits`，单张 multipart 参考图及可选 PNG mask |
| 视频生成 | multipart `POST /videos`、`GET /videos/{id}`、`GET /videos/{id}/content` |
| 语音合成 | `POST /audio/speech`，显式音色和 WAV 输出 |
| 语音转写 | multipart `POST /audio/transcriptions`，纯文本 JSON 或带时间戳 verbose JSON |

模型 ID 作为请求字段发送，允许包含 `/`；不用于拼接任意请求地址。图片结果转换为受校验的 PNG 并进入现有素材库。视频采用原网关返回的任务 ID 进行查询与内容获取，支持的创建规格为 4／8／12 秒、1280×720 或 720×1280，实际网关必须支持相同合同。

网关检查只执行显式的 `GET /models`，返回最多 200 个模型 ID 供核对，不自动创建模型或发起生成。没有此接口的网关可以手动配置模型。目录检查成功不代表生成成功。

## 部署准备

后端和独立 worker 使用相同配置。Compose 已提供以下环境变量透传；后端直接运行时需显式注入环境，不自动读取 `.env`。

| 变量 | 用途 |
| --- | --- |
| `MODEL_CONFIG_KEK_BASE64` | 独立保存的 32 字节随机 AES 加密密钥，以 base64 注入；没有默认值 |
| `MODEL_GATEWAY_ALLOWED_HOSTS` | 允许访问的私有／HTTP 网关，逗号分隔精确 `host:port`，如 `gateway.internal:4000`；不包含 scheme 或路径 |
| `EXECUTION_POLICY_FILE` | 已有报价、内容审核及账单策略文件，按现有流程安装 |
| `GATEWAY_MODERATION_COMMAND` | 未使用策略文件时，显式安装的本地或免费审核命令绝对路径 |
| `GATEWAY_MODERATION_SOURCE` | 该审核执行器的审核依据或版本说明 |
| `GATEWAY_MODERATION_EXPIRES_AT` | 审核授权到期时间，RFC 3339 格式 |

已配置 `EXECUTION_POLICY_FILE` 时继续使用其中审核规则；新网关报价由对应模型的保守上限生成，并绑定本次请求、网关、模型及版本。未配置策略文件时，只有明确注入上述审核命令、来源和有效期后才装配执行治理。审核命令沿用现有 JSON 输入／输出合同，必须审查实际模态；没有内置“始终允许”的审核器。费用上限、组织预算和内容审核未就绪时，页面显示具体阻塞状态。

HTTPS 公网目标默认只连接解析到的公网地址。HTTP 或私网目标需要部署侧精确白名单；DNS 解析结果直接用于连接，关闭代理和自动重定向。图片返回 URL 使用单独的公开媒体下载限制，不能携带网关密钥请求任意 URL。

先为组织设置预算，再确认本次费用上限。成功生成但没有权威费用证据时，预算继续保留未知占用；可在“模型使用统计”的“调用限制与费用账本”查看，不推断为免费或直接把预留上限当作已结算金额。

## 持久化、变更与统计

- 网关、模型、功能绑定保存在原模型配置存储的独立集合中；文件模式仍使用 `model-config.json`。
- 使用统计独立保存在 `model-usage.json`；数据库模式使用 `studio_model_calls`。已有 PostgreSQL 部署需先通过项目迁移命令更新 schema，再启动新版本。完整迁移和备份覆盖新增统计集合。
- 网关密钥由现有离线密钥轮换命令一并重新加密；密钥不得与数据备份放在一起。
- 网关和模型使用各自版本控制。功能绑定或其他网关更新只影响新任务，不使无关的已接收任务失效。停用、撤销或变更实际依赖会阻止相关任务继续发送。
- 统计保存网关／模型名称快照、功能、状态、耗时、HTTP 请求数、上游请求 ID 和上游实际返回的 token 用量。视频轮询属于同次执行中的 HTTP 请求，不增加生成调用数。
- 汇总基于全部筛选结果，调用明细每页最多 100 条。缺失用量为未知，各币种分别记录。累计调用上限是预留授权合计，不是估算或确认账单。
- 文件与数据库的第一版统计集合最多保存 10000 次执行。达到容量时拒绝新的受记录调用；不静默删除历史记录。生产长期运行需要配套归档策略。

本版支持启停与撤销，以保留引用和历史；未提供配置物理删除、批量导入、自动网关故障切换、完整单价计费或自动账单对账。网关视频恢复查询默认不假定免费，跨重启恢复需要进一步配置可信的查询费用合同；不会重新提交视频来代替恢复。
