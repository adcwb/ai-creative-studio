# 多 AI 网关、模型目录与功能绑定设计

日期：2026-10-30。状态：设计已确认，首版实施。本文保留目标设计；当前交付范围、部署方式和验证限制见 [首版使用说明](../../gateway-model-management.md)。

本次将模型接入改造为组织级的多网关管理。管理员先配置 AI 网关，再维护每个网关提供的模型，最后为每个创作功能选择使用的网关和模型。创作页面默认采用功能绑定，并在提交前明确展示本次选择。模型调用记录同时支撑使用统计。

## 1. 设计结论与现有差距

采用三个独立管理对象：`Gateway`（连接）、`GatewayModel`（网关中的模型）、`FeatureBinding`（功能绑定）。模型和网关采用稳定的内部 ID，界面名称和上游模型名称均不能充当主键。

现有代码已有加密凭据、组织隔离、配置持久化、任务执行授权及供应商适配器，可继续复用。但当前 `ModelConfigEntry` 把供应商、固定地址、单项能力、凭据和默认项放在一条记录中，无法表达一个网关共享凭据并提供多个模型；`IsDefault` 按能力设置，不能区分剧本和分镜。`ModelRuntime` 使用租户整体配置版本进行校验，任何配置更新都可能影响无关任务，需要改为按实际执行依赖检查。

实现方案比较：

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| 在旧模型记录上增加 Base URL | 改动小 | 重复维护同一网关凭据，功能默认项仍不清楚，不采用 |
| 在现有后端增加连接、模型、功能绑定三个对象 | 复用运行时、任务和组织权限；页面关系明确 | 需要迁移配置和调整解析规则，采用 |
| 新建独立模型服务 | 可以独立部署、扩容 | 当前增加服务、认证和运维成本，暂不需要 |

关系为：组织拥有多个网关；网关拥有多个模型配置；每个功能绑定一个模型配置；由该模型配置唯一确定网关。同一个模型配置可以被多个功能复用。

## 2. 模型管理页面

菜单及页面标题统一使用“模型管理”，路由保留 `/settings/models`。页面有“AI 网关”“网关模型”“功能绑定”三个页签，默认进入“功能绑定”。页头展示已启用网关数、模型数，以及已配置功能数。

### 2.1 AI 网关

表格字段：网关名称、服务地址、协议类型、凭据状态、已启用模型数、启用状态、最近连接检查时间、操作。

“新增网关”表单包含：

- 网关名称、Base URL，例如 `https://gateway.example.com/v1`；规范化后仅拼接一次 API 前缀。
- 协议类型：首批为 `openai-compatible`；该类型只决定可选适配协议，不声明所有模型具备所有能力。
- API Key：通过密码输入框设置，服务端加密；后续仅显示掩码，不回填明文。
- 请求超时、最大并发请求数、启停状态。

网关检查和生成试用分开：连接检查仅验证已声明的模型目录接口或专用健康接口；没有目录接口的网关允许手动维护模型。检查成功只表明该检查请求成功，模型实际生成能力由试运行单独记录。

网关地址保存时显示规范化后的实际请求根地址。更换地址要求重新设置凭据，防止已有密钥被直接发送到新地址。地址格式、目标访问策略、密钥加密条件、检查失败原因均由服务端返回并显示。

### 2.2 网关模型

顶部提供网关、能力和启用状态筛选。表格字段：模型显示名称、上游模型 ID、所属网关、能力、适配协议、启用状态、最近试运行状态、被哪些功能使用、操作。

“新增模型”先选择网关，再填写模型 ID。模型 ID 是网关实际接受的模型名称或别名，应按对应协议验证，不能沿用只允许字母、数字和短横线的限制；例如应允许符合协议要求的 `vendor/model-name`。模型 ID 仅进入请求模型字段，不直接作为任意 URL 路径拼接。

模型配置包含一组已声明的操作能力及对应协议配置。同一个模型条目可以同时具备文本生成和视觉理解能力；编辑图片、参考图生成、首帧视频等作为更细的操作能力记录。兼容性同时受适配器实现、模型配置和功能要求约束。

首批通用协议配置支持文本 Chat Completions、图像生成、图像编辑和明确版本的视频提交／查询／内容获取协议。语音及转写使用独立协议配置。未实现协议的操作显示“暂不支持”，不能通过勾选能力直接启用。

试运行结果按网关版本、模型版本和具体操作记录。例如文本成功不能把同一条目下的图像编辑标成已验证；修改地址、密钥、上游型号或协议后，旧验证结果保留为历史，当前状态恢复为未验证。

“同步模型目录”先展示发现结果，管理员选择需要导入的条目；同步不删除已有模型、不覆盖价格、不自动启用、不推断业务能力。目录不可用时保留手动录入。

### 2.3 功能绑定

每行一个业务功能，管理员在同一行依次选择“AI 网关”和“模型”。选择模型后展示该组合的执行状态及限制。

| 功能 | 所需操作能力 | AI 网关示例 | 模型示例 | 状态 |
| --- | --- | --- | --- | --- |
| 创意分析 | 文本结构化生成 | 主网关 | 文本模型 A | 可执行 |
| 剧本生成 | 文本结构化生成 | 主网关 | 文本模型 A | 可执行 |
| 分镜规划 | 文本结构化生成 | 备用网关 | 推理模型 B | 可执行 |
| 图像创作 | 图像生成 | 图像网关 | 图像模型 C | 可执行 |
| 角色参考图 | 图像生成 | 图像网关 | 图像模型 C | 可执行 |
| 镜头图片 | 图像生成 | 图像网关 | 图像模型 D | 可执行 |
| 图片编辑 | 图像编辑 | 图像网关 | 图像模型 C | 缺少图像编辑协议 |
| 镜头视频 | 视频生成 | 视频网关 | 视频模型 E | 执行策略未配置 |
| 配音 | 语音合成 | 语音网关 | 语音模型 F | 未配置音色 |
| 语音转写 | 音频转写 | 语音网关 | 转写模型 G | 可执行 |
| 图片分析／一致性检查 | 视觉理解 | 主网关 | 视觉模型 H | 可执行 |

表中名称均为说明关系的示例，不代表已经接入的供应商或型号。

交互约束：

1. 网关下拉只列出当前组织的网关；模型下拉只列出已选网关下、具备当前功能所需操作能力的模型。
2. 修改网关立即清空此前的模型选择。空网关、空模型、已停用和能力不匹配均不能保存为启用绑定。
3. 凭据或执行策略尚未就绪时，可以保存具备正确能力的绑定；状态明确显示具体阻塞项，生成按钮保持不可执行。
4. 每行显示“默认参数”和“允许创作时切换模型”。默认参数按功能保存，例如分镜的输出限制、图片尺寸、视频时长、配音音色。
5. 保存单行绑定立即生效于新任务，采用版本校验防止并发覆盖；成功后展示最后修改者和时间。
6. 功能绑定使用具体模型配置 ID。选中的网关由模型归属确定，不能保存互不匹配的两个独立默认值。

## 3. 能力与业务功能

模型能力回答“这个模型能调用哪些协议操作”，业务功能回答“产品在哪个入口使用它”。分镜规划是文本推理的用途；分镜图片和分镜视频是不同的生成操作。

能力采用集合，功能标识使用服务端固定注册表：

| 功能标识 | 页面用途 | 必需操作 |
| --- | --- | --- |
| `brief_analysis` | 创意／需求分析 | `text.structured` |
| `script_generation` | 剧本生成 | `text.structured` |
| `storyboard_planning` | 分镜规划 | `text.structured` |
| `image_generation` | 图像工作室 | `image.generate` |
| `character_image` | 角色参考图 | `image.generate` |
| `shot_image` | 镜头图片 | `image.generate` |
| `image_edit` | 参考图／遮罩编辑 | `image.edit` |
| `shot_video` | 镜头视频 | `video.generate` |
| `speech_synthesis` | 配音 | `audio.speech` |
| `speech_transcription` | 纯文本转写 | `audio.transcribe` |
| `subtitle_alignment` | 带时间戳字幕 | `audio.transcribe_timestamps` |
| `vision_analysis` | 图片分析 | `vision.analyze` |
| `consistency_check` | 跨镜头一致性检查 | `vision.analyze` |

图片遮罩、多个参考图、视频首尾帧、推理强度、JSON 输出等作为操作约束描述。界面根据当前模型支持情况显示参数，后端在接收任务和真正发送前再次验证。普通转写模型不能用于要求时间戳的字幕功能。

图像工作室、角色图和镜头图分别使用独立绑定，因此可以共用同一模型，也可以分配给不同网关。业务功能标识由服务端根据接口、操作类型和受校验的素材用途确定，不信任客户端提交一个低价功能名来替代实际操作。

## 4. 数据结构与一致性

所有对象归属当前组织／工作空间。管理接口只允许 owner/admin，普通创作者只读取脱敏后的可选模型和功能默认项。

| 对象 | 核心字段 |
| --- | --- |
| `Gateway` | `id`、`tenant_id`、`name`、`base_url`、`kind`、`enabled`、`timeout_seconds`、`max_concurrency`、`version`、凭据状态 |
| `GatewayCredential` | `gateway_id`、密文或已批准的外部引用、密钥版本；只存在服务端存储 |
| `GatewayModel` | `id`、`tenant_id`、`gateway_id`、`display_name`、`upstream_model`、操作协议配置、能力约束、价格配置、`enabled`、`version` |
| `FeatureBinding` | `tenant_id`、`feature_key`、`model_config_id`、功能参数、`allow_override`、`enabled`、`version`、修改者和时间 |
| `ResolvedSelection` | 功能、网关和模型 ID、版本快照、上游模型名称、协议、参数摘要、价格版本、可信 actor/tenant、费用确认信息 |

同一组织内 `feature_key` 唯一；同一个上游模型名称可以出现在多个网关中。模型名称可重复，内部 ID 唯一。网关有已配置模型时不能直接删除；模型正在被功能绑定或未完成任务引用时不能直接删除，界面列出引用并要求先调整绑定及处理任务。停用后保留历史任务和统计，历史记录继续使用保存的身份与名称快照。

凭据按网关保存一次，由其下模型共享。加密绑定组织、网关身份和规范化服务地址；更换地址必须重新提交凭据并产生新的网关版本。列表、错误、审计和统计不包含密钥、密文或完整请求内容。

版本规则：

- 网关地址、密钥、协议或启用状态变更，更新网关版本，阻止依赖旧连接继续发送请求。
- 模型 ID、能力、协议、参数限制或启用状态变更，更新模型版本，阻止受影响的旧选择继续执行。
- 功能默认绑定变更，只更新该绑定版本；已经接收的任务继续使用其固定选择，不重新解析新默认项。
- 不相关网关或模型更新不取消当前任务。现有租户整体版本可保留为旧管理接口的并发控制标识，不能继续作为所有新任务的统一撤销开关。
- 价格版本随报价和任务快照记录；提交时验证报价及确认上限，执行前再次校验。

本地模式延续单写者锁与原子文件提交；数据库模式延续现有组织隔离及任务、预留、入队事务边界。配置数据可在现有组织配置存储中演进；用量记录使用独立持久化集合，避免每次调用重写整个模型目录。

## 5. 创作页面与执行链路

创作页展示“当前功能：分镜规划；默认选择：备用网关 / 推理模型 B”。允许切换时，提供网关与模型的联动选择，切换只影响本次任务。成员不能编辑网关地址或密钥。未配置绑定时提示前往模型管理；真实模式不静默转为模拟生成。

执行顺序：

1. 服务端从业务接口推导功能与必需操作，读取当前组织功能绑定。
2. 根据默认绑定或允许的本次覆盖，解析模型及所属网关；覆盖也必须满足功能能力要求。
3. 合并模型限制、功能默认参数和本次输入，验证最终参数；生成请求摘要和费用预览。
4. 前端展示实际网关、模型、参数和费用上限；输入、选择或价格变更使旧确认失效。
5. 服务端接单时固定选择；验证组织权限、绑定规则、报价和预算，按既有持久化语义创建任务。
6. worker 按固定网关／模型版本执行，发送前复核权限、凭据、能力和执行许可。
7. 持久化生成结果、上游请求／任务 ID、调用状态、耗时和可获得用量；素材进入已有素材库。

功能绑定不能代替费用和审核就绪检查。执行准备状态应分别报告配置、凭据、操作支持、价格、审核和预算阻塞项，不能以单个含义模糊的 `live_enabled` 表达全部状态。

生成 POST 默认不自动重复发送、不自动切到另一网关。视频任务接收后持久化上游 ID，查询和下载固定回到原网关；重启恢复不能重新创建视频。结果未知保持未知，并保留费用占用，不从超时推断免费。

网关并发在实际 HTTP 发送层限制；数据库多 worker 模式采用共享租约／配额，不能只用每个进程自己的 semaphore。文本生成、轮询和下载分别设定超时；响应大小受限。

## 6. 网关协议与目标访问

网关 Base URL 在服务端校验、规范化并绑定到版本。请求不接受客户端任意路径、任意认证头或任意重定向目标。自建内网网关由部署侧显式配置允许的域名／网段；普通管理权限不代表可以访问任意内网地址。DNS 解析与实际连接使用同一访问约束，避免仅做字符串检查。

网关种类与模型操作协议分离：网关可能支持文本而不支持图片，或图片支持生成但不支持编辑；视频也可能使用不同异步协议。首批按明确的协议配置接入，不把供应商原生能力自动等同于网关已实现能力。

图像 URL 结果和视频下载地址使用单独的受控下载策略；不携带网关 API Key 请求任意返回地址。允许的输出域名单独配置，下载后做格式、大小及媒体检查，保存后供前端读取。

协议依据：现有适配器代码及 [LiteLLM 网关接口参考](https://docs.litellm.ai/api-reference)。该参考区分文本、图像生成／编辑和视频创建／查询／内容接口，只用于确认需要独立操作合同；最终对接以用户实际网关的接口说明和小样结果为准，不预设其视频协议或型号已可用。

## 7. 管理与运行时 API 合同

沿用 `/api/v1` 前缀、现有认证／CSRF 和组织参数。以下为待实现合同，正式实现时同步 `api/openapi.json`：

| 接口 | 用途 |
| --- | --- |
| `GET /model-management` | 返回管理视图、配置版本、网关、模型、功能定义及绑定 |
| `POST /ai-gateways` | 创建网关，凭据作为单次写入字段 |
| `PATCH /ai-gateways/{id}` | 使用 `expected_version` 更新网关；密钥操作为保留、设置、撤销 |
| `DELETE /ai-gateways/{id}` | 删除未被引用的网关，校验版本 |
| `POST /ai-gateways/{id}/check` | 执行已声明的非生成连接检查，记录其实际检查范围 |
| `POST /ai-gateways/{id}/discover-models` | 返回目录发现预览，管理员选择导入 |
| `POST /gateway-models` | 在指定网关下创建模型与操作配置 |
| `PATCH /gateway-models/{id}` | 使用 `expected_version` 更新模型 |
| `DELETE /gateway-models/{id}` | 删除未被引用的模型，校验版本 |
| `GET /model-features` | 返回固定功能定义、当前绑定及就绪状态 |
| `PUT /model-features/{feature_key}` | 使用 `expected_version` 保存单个功能的模型绑定和参数 |
| `GET /runtime-models?feature_key=...` | 返回脱敏的默认选择及允许切换的模型，包含可见网关名称 |
| `POST /runtime-quote` | 按实际业务请求解析选择并返回网关／模型快照及费用上限 |
| `GET /model-usage` | 返回按筛选条件聚合的使用统计 |
| `GET /model-usage/calls` | 返回分页调用明细 |

功能绑定请求保存 `model_config_id`，网关由服务端读取模型归属得到；如果前端另外提交网关 ID 供一致性检查，两者不符直接拒绝。创建模型请求中的网关 ID 必须属于同一组织。更新冲突返回 409，停用或失效返回具体问题代码。

生成和试运行复用同一解析、报价、预算、执行与用量记录路径；试运行带测试用途标签，使用合成输入，前端先确认上限。连接检查不调用生成端点；任何检查若会计费，转为上述试运行流程。

## 8. 模型使用统计

“预算与费用”菜单改为“模型使用统计”，保留 `/settings/billing` 地址兼容已有入口。页面以“模型汇总”和“调用明细”两个表格为主，预算配置放入管理员的“调用限制”折叠区域。

筛选项：日期范围、网关、模型、功能、项目、状态。汇总展示调用次数、成功／失败次数、成功率、平均耗时、P95 耗时、输入／输出 token、缓存／推理 token、图片数、视频秒数、语音时长和费用。

每条实际调用记录固定组织、功能、项目／任务、网关与模型身份及名称快照、协议、上游请求／任务 ID、调用类别、开始／结束时间、HTTP 状态、应用解析结果、用量和错误代码。统计不存完整提示词、响应正文或凭据。

逻辑生成任务和 HTTP 调用分开：视频创建一次为一个生成任务，轮询和下载另记为调用类别，不能把轮询次数显示为生成次数。HTTP 成功但结果解析失败，生成结果统计为失败；实际返回的可用用量仍保留。未收到上游用量时显示未知，不以零代替。

价格按网关中的具体模型及操作配置，允许同名模型在不同网关采用不同价格。文本按 token、图像按张及规格、视频按时长及规格、语音按已声明计量单位估算。金额采用定点数或整数高精度单位，避免逐次按分取整放大小额费用；各币种分别统计。

估算费用、上游报告费用和可对账的确认费用分别记录来源及价格版本。只有权威账单证据才能结算现有预算账本；使用 token 计算的费用可以显示为估算，不能自动冒充已确认金额。没有价格显示“未配置价格”，生成成功也不意味着免费。

报价规则按模型和有界请求参数计算，支持正常变化的提示词／素材输入；当前请求摘要继续用于绑定本次报价与输入。应移除必须由操作员逐个预录图片／视频请求哈希才能得到报价的产品使用障碍，同时保留费用上限、来源和有效期检查。

## 9. 旧配置迁移与部署

迁移前完整备份。旧模型记录转换为模型配置，保留原配置 ID 和历史关联；每条旧记录先创建一个对应的连接对象，以保持原地址、协议和独立凭据。仅当协议、规范化地址和凭据来源确实一致时允许管理员显式合并，不能因同一厂商就自动合并不同密钥。

迁移命令在受控服务端环境解密并重新封装凭据，不回显明文。文件和数据库两条迁移路径均做预检、版本校验及原子提交。已有密钥轮换、备份恢复、数据库健康检查和独立 worker 装配必须覆盖新增网关凭据。

旧文本默认项用于生成剧本、分镜和分析的待确认绑定；旧媒体默认项用于对应功能的待确认绑定。迁移不自动新增费用授权，管理员在功能绑定中检查并启用。旧任务保留旧执行协议直至处理完成；新版本读写兼容旧记录，禁止直接改写在途上游 ID 或将其切换到新网关。

Docker 和 1Panel 配置提供加密密钥注入、网关访问策略、执行策略与持久化目录；凭据由管理页面按网关加密配置，不需要为每个模型新增部署环境变量。具体真实网关地址、模型 ID、操作协议和价格由部署方填写。

## 10. 实现拆分与验收

按依赖顺序推进四个可验证增量：

1. 网关／模型／功能绑定的数据合同、持久化、迁移、管理 API 和三页签界面。
2. 功能解析接入现有创作入口；统一网关客户端，先打通文本剧本与分镜、图像生成，再按实际网关协议接入视频。
3. 调用记录、用量采集、动态参数报价、统计 API 与表格页面。
4. 部署配置、故障恢复和真实小样验收。

必要验证：

- 两个网关拥有相同模型名称，功能仍准确调用所选网关和模型；同一网关下多个模型的 Key 来源一致。
- 剧本、分镜绑定不同网关；角色图、镜头图绑定同一网关的不同模型，均在实际 HTTP 请求中验证目标、认证和模型字段。
- 跨组织读写及模型归属错误被拒绝；编辑者只能使用管理员允许的本次覆盖。
- 切换网关清空模型；不支持编辑或时间戳的模型不能绑定到对应功能。
- 修改功能默认项不改变已接收任务；停用网关／撤销密钥阻止相关后续发送；修改无关配置不打断任务。
- 视频轮询／下载始终使用原网关和上游 ID；重启后不重复创建；429、超时和结果未知不盲目重发。
- 响应中的 token 用量、缺失用量、结果解析失败、媒体用量、估算与确认费用能正确进入表格；统计按原币种隔离。
- 文件与 PostgreSQL 配置重启、迁移、密钥轮换和 worker 恢复通过；桌面和手机完成三步配置及创作选模。
- 更新 OpenAPI 并检查前后端合同；已有单元测试、类型检查、构建和针对性集成测试通过。

协议验证采用真实应用代码连接本地 HTTP 模拟上游，覆盖正常响应、鉴权失败、限流、超时和无效结果，并记录实际上游请求。真实验收再使用用户配置的网关、模型和费用上限，分别完成文本、图像和视频小样。模拟验证、连接检查、真实生成及费用对账分别报告证据。
