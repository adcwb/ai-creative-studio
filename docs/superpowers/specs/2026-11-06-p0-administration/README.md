## 已落地设计与接口

首版66df603已推送；本节实现随后经安全复审强化，安全修订的最终CI状态以交付报告为准。后端配置独立路由`/settings/backend`，偏好`/settings/preferences`，团队空间`/settings/spaces`，成员`/settings/organization`。系统设置树始终提供后端入口，未授权账户显示权限说明，不请求全局配置。部署管理员由受保护的`STUDIO_ADMIN_USER_IDS`固定不可变账号ID定义，旧邮箱名单不再授权，与空间所有者彻底分离。配置按版本CAS写入私有0600文件，不在浏览器保存敏感草稿，服务器从不回显密码、Token、密钥、含凭据或查询参数的URL。保存并不热加载，需API/worker共同重启。镜像构建注入commit revision，偏好页显示前端revision，管理员配置页显示API revision；本地未注入版本显示unknown，不能据此推断生产已升级。

`GET /organizations/{id}/access`返回当前空间类型、角色、实际权限和成员版本；成员PUT支持`expected_version`，新界面发送CAS版本，旧客户端可省略。团队创建沿用POST `/organizations`，GET `/spaces`返回当前用户可见空间。个人空间仅自己可用，不可邀请；团队按成员共享，切换不移动资源。旧组织保持原ID、资源和成员，统一作为team，不能依据名称或仅一位成员自动改成personal。旧用户再次登录时补建独立个人空间。此轮不实现商业套餐、席位数、项目额度、付费或跨空间资源搬迁。

固定角色只在服务端定义，未知权限默认拒绝。PostgreSQL新增`studio_rbac_roles`、`studio_rbac_permissions`、`studio_rbac_role_permissions`、`studio_space_access`、`studio_space_memberships`；角色/权限关系和成员关系是实际授权来源，静态矩阵作为权限上界。约束保证每空间所有者存在且唯一、个人空间只有本人、一人至多一个个人空间。JSON组织快照是同事务兼容/导出表示，不作为第二套权限来源。文件模式保留同一权限矩阵、个人隔离和版本语义。重复初始化不恢复被撤销的关系或权限。

创作入口默认`CONTENT_MODERATION_MODE=disabled`，不调用审核器、不伪造allow。`required`保留真实审核，缺少审核器、合同过期或未知模式启动失败；显式配置required的部署仍会启用校验。原有幂等派发凭证、授权复核、能力匹配、租户隔离、媒体来源、格式、SSRF和取消保护继续生效，不执行预算、报价或额度预留。关闭审核不代表上游供应商取消自己的策略。

## P0安全复审与迁移（2026-11-06）

已在完全隔离的66df603基线二进制复现两条路径：任意Origin可携带会话读取CSRF；公开注册命中管理员邮箱可获得deployment_admin。未操作在线数据，未读取真实凭据。安全模式现按FRONTEND_ORIGIN + AUTH_ALLOWED_ORIGINS显式完整来源匹配，拒绝null、通配符、路径/查询/用户信息及未列出的源；不从Host、X-Forwarded-Host或Referer猜测信任。所有带Origin的私有读取、预检与写请求均检查，写请求仍需CSRF。签名媒体能力URL仅GET/HEAD公开读取并允许仅Range预检，响应允许*但不允许credentials，其自身签名、有效期和当前来源授权仍检查。demo不提供身份隔离，不能作生产替代。

跨域部署迁移示例：FRONTEND_ORIGIN=https://studio.example.com；AUTH_ALLOWED_ORIGINS=https://team.example.com,http://localhost:5173。必须逐项核对实际前端域名与端口，不能填*或null。缺少主来源/来源格式错误会拒绝启动；未列出的来源会返回origin_denied。与旧版任意凭据CORS不兼容是必要安全修正，需在升级前配置，不能悄悄降回全放行。

管理员迁移：旧STUDIO_ADMIN_EMAILS不再授予权限，只阻止保留名称被公开抢注；升级前已注册的同名账号也不会自动升级。部署人员须通过可信渠道核对账号ID，再设置STUDIO_ADMIN_USER_IDS；此项仍不能通过网页写入。需要新建受控账号时，先停全部API/worker与自动重启控制器（PG先完成schema init），运行镜像内bootstrap-user命令，从stdin输入新密码，命令仅输出user_id，不自动授权、不留下登录会话、不覆盖同名账号。密码不能放命令参数、Git、页面或日志中。

`-confirm-stopped`仅要求操作者确认，不会自动停止或禁止PostgreSQL全实例写入。工具的store.lock只锁当前DATA_DIR，无法排除其他DATA_DIR中的API、worker、后台写入程序或自动重启控制器；PostgreSQL事务也不能代替停写。操作者须先停止全部writer并保持停写，不能把参数或本地文件锁当作集群级强制停写证据。

```bash
# 在受控环境且所有writer已停后；此处只是操作说明，未执行生产创建。
read -rs bootstrap_password
printf '%s' "$bootstrap_password" | /app/bootstrap-user -email operator@example.com -confirm-stopped
unset bootstrap_password
# 将返回的账号ID加入部署环境STUDIO_ADMIN_USER_IDS，重启同版API/worker，再登录。
```

团队身份：每次成员写入都要求对方的不可变user_id，且邮箱与该ID当前目录一致；不再按全局邮箱搜索来选择授权对象。本地邮箱未验证，ID须通过可信渠道核对；SSO邮箱也不能代替ID。新增UI要求输入ID，已有成员“调整权限”固定服务器返回的ID。未实现邮件所有权验证/SMTP/证件核验，不宣称账号ID等于自然人真实身份。旧邮箱-only客户端必须升级；带ID但不带expected_version的旧请求仍兼容为串行最后写入，新前端始终CAS；角色撤销与管理权限在事务内重新检查。
