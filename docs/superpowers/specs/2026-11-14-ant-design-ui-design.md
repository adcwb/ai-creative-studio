## 目标与范围

创作者沿用既有操作路径，获得统一的输入、选择、按钮、反馈与确认交互。管理员继续管理真实网关、凭据与功能绑定；原型的示例数据不得进入产品。

本次交付包括组件库基础设施、三套现有主题与中英文适配、共用确认弹窗、图像创作表单/模型选择/历史操作、模型管理表格与编辑器。工作流画布、遮罩、时间轴和其他业务模块沿用现有实现，共用确认弹窗随基础设施统一。此次不宣称全站每个原生控件均已迁移。

## 设计决策

1. 使用 Ant Design 6 和 Ant Design Mobile 5；保留 React 19、TypeScript、Vite、React Router。锁定实际安装版本。保留森林、纸张、放映厅主题，沿用用户现有偏好存储；不添加原型专用的蓝色主题。
2. Ant Design ConfigProvider 接收当前账号主题与语言。Mobile 的 CSS 变量采用相同语义色；不依赖两库自动同步。弹层挂载到当前原生 dialog 或主题容器，下拉菜单挂载到可接收指针事件的弹层内容，防止原生 top layer 与 Portal 冲突。静态命令式反馈不绕过主题上下文。
3. 桌面端采用标准按钮、Input、Select、Checkbox、Tabs、Tag、Alert、Table 与 Modal。网关列表改为 Table；模型目录与功能绑定保留既有语义表格及手机卡片排版，内部控件采用组件库。窄屏保持单列创作布局；编辑器使用 Mobile Popup 底部面板。断点统一为 760px；弹窗打开时选择展示容器，打开期间不因窗口变化更换容器，以保留草稿。请求、草稿、轮询状态继续复用。
4. 保留原有中文翻译键与英文对应文案、语义标签、错误说明、服务 readiness、权限和真实请求状态。凭据保存继续清除明文输入，未知结果不得伪装为成功。
5. 对原生全局控件 CSS 增加组件库排除范围；保留未迁移控件的样式。主题配置负责库控件的颜色、圆角和大小，专用 CSS 仅处理布局与业务内容。
6. 共用确认框保留取消优先、忙碌禁止退出、焦点恢复、错误重试。迁移编辑弹层须覆盖目录滚动位置、未保存修改确认、嵌套 Esc、键盘循环与背景滚动。
