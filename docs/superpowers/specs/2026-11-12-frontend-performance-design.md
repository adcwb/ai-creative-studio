# 前端读取与加载优化

用户已要求按代码核对后的优先级完成优化，并将本轮和此前页面改动合并为一次 GitHub 提交。

## 方案与范围

保留现有路由和写入状态，仅收敛读取副作用。相较于拆掉 ImageWorkspace 父路由，这能保留跨页面草稿与 uncertain 请求的幂等标识。采用一个可测试的轮询调度器和 React hook，逐个迁移任务读取；英文词典整体动态加载，比领域级拆包更容易保持同步翻译入口的一致性。模型目录先做有界、短期的共享缓存和请求合并。

不在本次改变生成、上传、CAS 保存的写入协议，也不引入后端缩略图接口。大型组件和通用 mutation 的重构应根据测量与恢复行为测试单独推进。

## 行为约束

- 图像任务和素材只在 /studio、/assets 读取。隐藏页面暂停，恢复后立即刷新；读请求不重叠，清理时取消且不能接纳过期结果。
- 失败指数退避，权限类错误停止自动重试；原先任务完成停止的行为保留。读取消不得影响正在执行的写操作。
- 中文启动不下载英文词典。英文首次启动等待词典；交互切换等待加载完成后再生效，不卸载已有编辑页面。失败可重试，快速切换以最后一次选择为准。
- 模型目录按账号、空间、功能隔离，共享并发读取，短期缓存；会话及配置变动失效，刷新同时通知其他使用者。
- 列表图片按需加载且保持布局占位；表单补可定位的错误提示。

## 实施与验证

1. 公共轮询调度器、fake timer 测试、路由和可见性控制、迁移读取。
2. 英文按需加载及加载失败/切换竞态验证。
3. 模型目录缓存和失效测试。
4. 图片与错误关联、针对性大对象计算缓存。
5. lint、类型检查、单元测试、生产构建、路由/模型/设计/性能浏览器回归；检查提交文件后提交并推送。
