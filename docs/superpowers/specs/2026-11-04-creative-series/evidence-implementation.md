## 创作者流程

先编辑资料的创作含义，再按需选取能支持判断的原文。引用准确仅代表确有这段文字，不能自动证明角色认知是客观事实，也不代替作者判断。正式资料与AI建议采纳表单共用同一证据编辑器，不由模型擅自填写新的可信证据。

1. 选择本系列剧集，明确读取已保存的剧本版本目录。目录只含版本、标题、当前稿/稳定场次标记，可以加载更早版本，不把所有历史正文送到浏览器。
2. 明确选择一个版本，再选择稳定场次。展示其实际标题、动作与对白原文；可以选入整段，也可以输入某一原文段落内的连续片段，不允许拼接、改写或空引用。
3. 明确添加或替换后，引用进入当前资料草稿；仍需保存正式版本。已有证据可重新读取固定版本后编辑或移除。读取、比较和选取不恢复剧本、不升级旧历史、不发起模型请求。
4. 保存时服务端重新核验当前空间和系列归属、历史版本、摘要、场次及原文。当前剧本已改写不改变真实历史引用；伪造版本、场次、摘要或原文不能保存。来源已经不存在时保留原草稿并明确报错。
5. 使用既有原请求恢复合同：未确认的保存锁定正文和证据，跨刷新保留原key/body；回执恢复不覆盖后来的正式稿。资料历史仍不可变，移除证据会追加新版本。

本集上下文的“明确带入其他资料”现在独立读取分页正式资料目录，不要求先有预览或旧快照。已选项目单独显示，可移除，刷新或加载更多不会清掉选择。故事圣经/必需资料仍由编译器优先核对；明确选择不绕过归档、叙事范围、其他剧集选角或原生输入容量。目录显示的是读取时的当前正式版本，创建快照时固定实际解析的head版本；并不伪称选择了某个未读取的历史正文。

## API与实现落点

| 接口 | 合同 |
| --- | --- |
| `GET /series/{id}/story-evidence/episodes/{episode}/scripts` | 当前授权空间和系列内的剧本版本元数据，默认20/最多100条一页，版本降序；`cursor`为继续读取的版本边界；无正文 |
| `GET /series/{id}/story-evidence/episodes/{episode}/scripts/{version}` | 显式读取一个真实稳定历史版本，返回服务端计算的`script_sha256`、剧本与剧集/版本身份；不存在404，缺少稳定场次或无效参数400 |

实际URL前缀为`/api/v1`，均要求现有认证与`space_id`。viewer可以读取当前可访问来源，不能写正式资料；撤销成员后不能通过历史URL读取。外系列或外空间引用不予返回。目录页大小是传输工作集，不是系列历史数量限制。未知或有歧义的历史不猜测；不在GET里写入或制造稳定ID。

- `backend/internal/application/story_evidence.go`：范围核对、元数据分页与单版本只读接口，复用既有真实`structureSourceLocked`历史来源解析。没有新表、凭据或供应商接口。
- `backend/internal/application/story_store.go`原有保存验证与`story_decisions.go`显式采纳验证继续执行，客户端可选列表不是永久写入授权。没有放宽现有CSRF、CAS、原回执、引用和租户检查。
- `frontend/src/features/series/StoryEvidenceEditor.tsx`：共用来源读取/选取/替换/移除表单，服务端摘要不要求用户手输；切换来源取消旧读取，完成前不改正文，替换时再次确认草稿条目仍为原条目。
- `StoryContextSourcePicker.tsx`：分页选择与独立已选清单，读取失败可刷新，刷新时暂停旧游标加载，不丢失已选身份。
- `StoryWorkspace.tsx`、`StoryDecisionEditor.tsx`接入，沿用既有`series-form`、`story-history`、`editing-note`与原控件，不新增视觉系统或样式文件；中英文同步。
- `api/openapi.json`增加两条只读合同与三个严格schema；实际HTTP测试验证成功与失败响应。

## 兼容与边界

旧故事资料和证据无需迁移；新前端应与提供新只读接口的后端一起发布。既有剧本/资料/采纳写入格式不变，本轮不执行生产数据库操作。新接口复用当前项目历史存储；分页避免全历史正文上网，不代表已解决剩余scope存储与全200集生产容量问题。

旧剧本若没有稳定场次，目录明确标识不可用于固定场次引用。需要时由创作者在项目中显式恢复为新稿并升级身份，旧历史保留；不能自动编造老场次与新场次的对应关系。当前证据合同引用剧本场次，不新增任意URL或文件抓取、外部资料导入、媒体/声音使用许可。人物/风格/声音使用权仍须在T33C2单独落地并在实际派发前核对。

## 后续T33C2依赖核对

当前`modules/library/model.go`只支持character/product/scene；`VoiceNotes`仍是文字，不能据此授权声音克隆。资产版本/项目绑定已有固定版本和字节摘要，但`library_binding.go`复制媒体并不等于可撤销使用许可，不能把复制后的项目图片当成永久授权。`creative_controls.go`已有真实参考图、首尾帧和部分供应商视频参考适配；`provider_creative.go`现有语音是固定音色而非自定义授权声音。后续应分别实现当前可撤销许可、风格/声音卡与版本、显式媒体用途选择和每次实际派发的当前许可/字节/模型能力核对，再进入导演编排；保留未知结果不自动重发。不得仅增加说明文字就勾选T33C2，或把文字风格/表演意图宣称为原生锁脸、参考视频控制或声音克隆能力。

另已核实`library.ValidateReferences`仍有每版本12份参考的固定数量判断，`library_binding.go`仍按旧图片复制路径读取。本阶段未改变它们；T33C2扩展必须结合分页引用/受控流式读取审查并移除自设数量门槛，保留实际模型单次输入和解码工作集保护，不将模型一次参考数量当成资产库容量。
