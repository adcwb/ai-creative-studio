# 实施记录：文件资产库分片存储

日期：2026-11-05。开发基线：`2bbb483dd2568d03fd929b18bf69ab450ab8432f`。状态：T03的一项基础依赖完成，完整P0A和长篇制作规格仍未完成。本阶段仅本地提交，不推送、不部署、不执行生产迁移或付费模型调用。

## 解决的问题及实现

原文件资产库的每次读取、版本保存和回执查询都会装入整个空间的`library/{space}.json`，保存也重写全库；累计JSON超过64MiB后拒绝继续保存。现在[文件仓库](../../../../backend/internal/persistence/libraryrepo/file.go)采用`library/{space}.entities/{asset}/`的不可变事务记录。每条记录一次提交资产头、可选新版本及原始请求回执，临时文件fsync后通过不可覆盖硬链接发布，再同步目录。当前资产只解码最新记录，历史分页只解码选中的版本；查询不会为了一个角色读完其他角色和全部历史正文。

文件模式使用每空间的进程间flock，两个独立仓库实例共同遵守版本CAS与空间级幂等键；锁等待尊重请求取消。原请求结果不确定时仍用原键核对，重放再次同步已可见记录的目录，不能仅凭可见性宣称持久提交。版本ID按完整身份比较，包含连字符的`v1`和`v1-other`不会混淆。损坏、未知格式、符号链接、FIFO及尾随JSON明确报存储错误，不把它们重置为空库。

累计资产、版本、回执或JSON大小不再是保存准入条件。单条记录的2MiB解析防护大于当前合法卡片字段的编码大小，约束单次解析内存，不约束库的累计规模。文件目录枚举和新请求回执/版本身份检查仍扫描文件名；本阶段没有将文件模式宣称为任意规模下的恒定时间索引。

[迁移与引用清单](../../../../backend/internal/persistence/libraryrepo/migration.go)识别旧快照和新事务目录。新格式的启动引用清单逐版本读取并去重引用，避免构造全空间历史正文快照；离线SQL导入/导出仍可构造完整中间值，是后续迁移内存优化范围。PostgreSQL原有实体表及对外API保持兼容，不新增DDL。移除了已经没有调用者的资产库累计容量错误，技术输入错误不再误称为“资产库容量已达上限”。

## 升级和恢复合同

首次访问旧文件库时，在空间写锁下验证旧数据，并构建私有暂存树；全部记录、格式标记及目录同步后，一次rename发布。原`{space}.json`保留原字节作为恢复副本；新目录发布后为唯一有效来源，旧文件不能覆盖新版、复活归档或改写原回执。暂存失败不接受半个库；未发布的临时树不作为作品读取。

离线`file → PostgreSQL`导入只读源文件，包括事务回滚时，不为导入创建分片目录或锁文件。`PostgreSQL → file`在调用方的私有暂存目录输出新格式，由外层迁移完成后统一发布。原生PG备份合同不变；文件备份必须包含完整DATA_DIR，不能只备份旧JSON。升级前按现有规范停服备份并在副本演练；本阶段没有操作生产环境。

禁止直接用旧二进制对升级后的目录继续写入：旧程序会忽略新记录而产生分叉。回退须停止写入并恢复完整旧备份，或使用已验证的前向修复。保留旧快照会暂时增加实际磁盘占用；旧快照/中断暂存树的生命周期清理仍需后续工具，不以累计容量配额替代真实磁盘错误处理。
