# 配音识别与对齐的来源固定

日期：2026-11-05。代码基线：`df1894b3f7f0f863d1714c88bbdb8fac33cf649b`。对应T33C2D1，接续[素材来源追溯](asset-lineage-implementation.md)及[当前使用声明](asset-use-implementation.md)。这是独立音频消费链的基础子项；**C2C2原生人物/风格/声音控制、C2D整体、编剧导演/制作编排及200集完整生产验收尚未完成**，不能据此推送。

## 创作行为

创作者从已保存镜头的配音创建识别、纯文本转写或已知文本强制对齐任务。系统固定实际配音文件和资产库祖先使用修订；排队期间撤销、过期或重新授予时，旧任务不能借新许可继续发送。创作者核对后可用新意图创建任务，原请求始终返回原任务和已保存状态，不重复识别。

声明界面增加“配音识别与对齐”（声音卡）或“衍生配音识别与对齐”（其他卡）用途。其他卡也可能是生成配音的创作祖先，因此可明确允许其衍生音频被分析。这个范围不包含声音参考合成、原生音色生成、声音身份或克隆权，也不把图像生成声明隐式扩大为音频分析。普通直接上传且没有库祖先的配音不要求建立库卡或声明；认证、权限和真实字节核验继续保留。

C端仍使用现有资产卡、复选框、内联状态与恢复交互，不引入新的确认页、费用门槛或视觉系统。拒绝创建时返回明确409和可操作提示，不能误报为“保存结果不确定”而让用户反复核对未接纳请求。固定字段不会展示为创作表单里的技术配置。

“按文本估时”仍是明确标示的本地分配工具，不读取音频、不调用ASR、不需要音频分析声明，也不会被当作真实识别结果。已完成的字幕建议、原任务、原回执和历史配音保留；撤销之后仍能显式把已有字幕应用到匹配时间轴，不自动重发或改写剧本。

## 接纳与派发

`alignment_store.go`原本持有媒体锁与对齐锁执行接纳，不能在锁内直接调用旧素材来源解析（后者还可能读取媒体、core、creative和迁移记录）。本阶段采用三步：

1. 持现有锁校验输入、原回执、时间轴版本、镜头、准确配音和已选模型；已接受原key优先返回，不重新准备来源。
2. 释放锁后按请求上下文准备实际音频SHA/MIME及所有库祖先的固定版本和当前`audio_analysis`授权修订。
3. 重新持锁按相同原始请求摘要检查原回执，再核验时间轴版本与配音。来源准备失败时也先检查并发已成功的原回执；版本变化则不发布任务/队列。只有完整固定后才原子写入任务、回执与PG队列。

内部准备类型不属于`AlignmentInput`，不改变旧请求JSON摘要。客户端不能提交`audio_sha256/library_media_pins`；`AlignmentTask`新增这两个可选只读字段，老历史省略仍可读。任务响应、列表、回执和运行上下文深复制pins及模型选择，不能用响应对象修改保存的权限。

文件与PG API、独立worker都在加载完整仓库后配置同一来源回调。worker开始执行时重查当前字节与声明；读取到内存的真实音频还必须匹配固定SHA/MIME，避免文件在准备后变化。实际ASR HTTP发送与本地强制对齐命令启动再复核；受管网关继续保留当前成员/模型/审核/幂等执行许可。重新授予产生新修订，不能复活旧pins。没有来源摘要的旧排队意图不补造今日许可，返回明确`alignment_source_unpinned`，历史回执不变。

文件模式中断仍按既有语义将未完成真实任务标为`execution_interrupted`，禁止自动重新POST；没有伪装成可安全重跑ASR。PG沿用租约fence、派发状态和同事务终结，已终结任务不再次claim；本阶段没有改变不确定结果的恢复规则。

- `ExecutionGovernor.Execute`在输入审核前、后复核来源；运维配置的输入审核命令也核验，不能通过审核消费已撤销素材。`ReviewResult`继续允许安全审核已接受的结果，不以撤销为由丢弃结果或触发新生成。账单核对不发送prompt/media，费用预留没有恢复。
- `provider_local_transform.go`已有命令启动前复核，新的独立对齐上下文现在接入该保护；图像/视频/语音等既有CreativeJob保持原派发、输出血缘和已确认上游只读恢复保护。
- 其余直接HTTP/命令按用途核对：对象存储/分段上传与结果保存、模型目录GET、文本审核、发布连接器、ffprobe/ffmpeg本地剪辑和数据库备份各有独立职责，不是新的模型生成入口。本阶段不把历史读取、备份、结果保存或显式本地剪辑等同于新模型输入。第三方发布授权不因本项被删改。
- 人物/风格/声音卡的原生输入选择、真实供应商参考能力/音色参数及其完整派生消费闭环仍由C2C2实现；不能把这份消费者核查当成未实现链路已经接入。
