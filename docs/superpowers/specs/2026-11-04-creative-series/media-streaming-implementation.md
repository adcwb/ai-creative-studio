# 编辑素材与上游媒体：移除旧字节门槛

日期：2026-11-06。代码起点：本地`dde64dd3a94134265e8ee2fd76ad00c8129c6f2a`；远端仍为`d7b530a54eb2ee1091f659d48e749ff771978df1`。这是用户进一步授权的本地修复，**不推送、不部署**，不改变之前远端CI失败和镜像跳过的事实。它接续[CI失败后的实际缺口核查](revision-implementation.md#ci-failure-audit)，不把本节实现倒填为此前已经完成。

## 本轮范围与创作者行为

- 图像结果“继续编辑”、照片旋转/裁剪和蒙版保存不再以32MiB拒绝文件；蒙版编辑器及校验的旧4MiB门槛也删除。PNG/JPEG、解码像素、同尺寸蒙版和透明/不透明区域要求仍保留。
- 沿用已有页面、按钮、绿色面板和移动端纵向布局，没有新增样式系统。普通素材的可暂停上传入口保持；上述工具产生的Blob也改走现有分块会话协议。
- 保存和继续编辑不生成模型请求。编辑原图在上传完成响应丢失后，以原项目、原请求键和同一文件摘要恢复；不会重新创建项目或重复素材。
- 新发现的成功跳转问题已修复：继续编辑完成后同步释放自己的导航任务，再进入工作区，不再被自己的忙碌状态拦住。其他工具/未保存草稿的保护保持独立，不能用清除全部导航状态来通过测试。

## 浏览器与上传

`frontend/src/features/uploads/uploadBlob.ts`使用现有`FileSHA256`按8MiB切片校验，再按服务端会话分块上传；不把整个Blob转成ArrayBuffer或base64，也不增加总文件额度。浏览器下载原图使用Blob，由浏览器管理其存储；这不是承诺浏览器完全零拷贝或可编辑无限像素。Canvas仍按实际解码像素使用内存。

每次调用沿用原创建键、相同元数据、确定的分块键和完成键，已接纳的会话可直接返回原素材；进度不前进/非法块尺寸会停止，不无限循环。继续编辑持久记录协议版本：升级前未确认的raw上传仍在原raw回执域重放，不能直接切到新会话域而产生重复素材。普通工具的Blob保留在当前页面中；跨刷新恢复不承诺自动重建已经丢失的本地Canvas内容。

调用点为`ContinueImage.tsx`、`MediaStudio.tsx`及`ProductionBoard.tsx`。前者保持项目身份和恢复键，后两者保留原素材用途、角色、镜头及蒙版元数据。现有可恢复上传协议、当前权限、完整文件校验与素材登记事务继续生效。

## 上游响应、审核与入库

`provider_media_stream.go`增加可选`SpeechTo`/`DownloadVideoTo`协议。OpenAI兼容网关和OpenAI二进制语音/视频响应以64KiB缓冲写入私有临时文件，取消、截断、无效签名、写入失败均返回错误，不发布半文件，不自动重新POST生成。保留HTTP错误分类、超时、禁止重定向/透明POST重放，以及原有运行权限与只读恢复ID限制。

Ark、MiniMax、Google的视频下载也安装流式下载器。原有公网地址验证、DNS地址固定、无代理、无凭据CDN请求及重定向限制继续使用；运行器同时包装新的流式回调，不能从旧`download`字段之外绕过撤权。旧`[]byte`接口作为兼容入口保留，正常创作worker优先使用流式接口。原生JSON/hex语音协议的既有边界没有被冒称为全部改成二进制流。

结果在登记前校验媒体格式、编解码/尺寸/时长并实际完整解码；RIFF WAV在已声明有限长度时核对实际字节，避免分块HTTP正常结束但容器本身已经截断；合法的未知长度流式WAV通过私有校验副本补齐长度后解码，原始字节与摘要不改写。上游未声明长度时，不能声称仅凭EOF判断全部远端截断。解码仅允许本地file/pipe协议。随后审核实际字节，最后使用现有`addAssetFile`的原键、库来源、租约围栏和事务登记。出错或拒绝清理本次私有临时文件，不创建可见素材；未知S3写入仍沿用已有不可变对象/原键恢复语义。

`governance.ExecutionMedia`新增只由可信应用装配的非持久`MediaStream`，包括原字节SHA/长度和私有打开回调，不从公开JSON接收，不向审核命令泄露路径。摘要与旧Data字节摘要一致；实际发送审核时重新核对长度/SHA。标准`ExecutionPolicy`向命令分块编码**同一Data(base64)/MIME JSON合同**，不会只传摘要冒充内容审核。大媒体不再因整个base64 JSON超过旧内存上限而拒绝，也不把完整媒体复制进Go JSON缓冲。

未声明支持流式内容的自定义进程内审核器对大媒体fail-closed；声明支持的可信实现负责消费实际流，标准命令审核器无需新增配置字段。测试专用审核器同步增加实际读取和摘要检查，未通过允许空Data来绕过审核。没有恢复成本/预算预留逻辑。

## 参考原图和蒙版派发

只删除上传门槛仍会在参考派发时遇到旧的内存读取限制。因此网关与OpenAI单参考/蒙版新增`GenerateWithReferenceFiles`，从当前项目私有文件流式构造multipart，保留原字节、顺序、MIME和JPEG/PNG扩展名；不创建可重放生成POST。蒙版校验改为按已验证参考尺寸解码PNG，并验证透明和不透明区域，不用4MiB替代像素安全检查。公开OpenAPI说明已同步，字段结构未改。
