## 本批实际代码

- `backend/internal/modules/series/model.go` 定义系列、季、集独立实体、状态、版本、同父级编号和输出意图。默认90秒、1080p、9:16；1080p/1440p/1800p/2160p 及横/竖/方画幅可表示；60–120秒是创作目标，不是拒绝更长意图的产品额度。JSON 安全整数、字段格式和能力档位仍校验。
- `backend/internal/persistence/seriesrepo` 提供按空间、种类、父实体、状态及游标分页查询，CAS 更新、同父级换位和稳定幂等回执。创建子实体继承父级输出意图，已创建子实体不随父级更新暗中改变。系列/季归档停止新建下级，已有项目仍可读取。重排同时检查集与父级版本、更新下一个编号，避免第7集移到第300集后又产生相同编号。
- PostgreSQL 使用 `studio_series_nodes` 的**每实体独立行**，而非新建整体 scope；类型字段区分 Series/Season/Episode。空间/父类型/父ID/系列ID 的复合外键约束层级归属，同父级编号的延迟唯一约束允许原子换位；索引服务目录分页。`studio_series_receipts` 单独保存回执。此为原设计三表的物理布局收敛，不改变三个领域实体和独立版本。
- 文件模式按实体追加版本行，以持久提交标记一次公布子实体、父计数和回执。未完成行不成为已接受结果；已提交数据损坏、路径符号链接和非法标识报存储错误。单条解析有界，不设置整个目录8MiB或201集等累计门槛。当前文件分页会枚举相关实体头部元数据并排序，不读取剧本/媒体；不是恒定内存或完整长期容量验收。
- `backend/internal/application/series_store.go` 的内部 `CreateSeriesEpisode` 创建每集独立 `Project`。集和项目使用同一不透明ID（不同实体类型），Project 保存只读 `series_episode_id`，独立项目内部版本从1开始。PostgreSQL 的目录/父编号/回执与既有 Project 在同一核心事务提交；延迟外键阻止目录引用跨空间或缺失项目。文件模式先持久 preparing 意图，项目落盘后才公布 ready；启动恢复完成已接受关联，期间隐藏未就绪项目。重试返回当前项目，不用最初标题/简报覆盖用户后续编辑。集的当前标题/简述以 Project 为准，目录中的创建种子只用于恢复；后续 HTTP 详情必须投影 Project 当前值，不能把创建种子当作当前标题。
- 目录创建只保存元数据，**不自动生成剧本、分镜、图片或视频**。未来生成继续使用现有真实网关；没有增加模拟生成入口或成本/额度校验。
- `postgres_migrate.go` 注册系列文件↔PG的离线迁移，保留当前实体、原回执及编号；验证使用元数据副本，源目录不被构造器改写。存在 preparing 集时拒绝迁移，须先在原文件模式恢复；不凭空创建项目后继续切换。PostgreSQL 缓存拒绝隐式装入本地系列目录。`Project` 的只读关联同步至 OpenAPI 与 TypeScript。

## 使用与迁移边界

本批**不注册系列 HTTP 路由、不展示系列新建按钮**，以免用户进入尚未适配外部集号和输出快照的半成品工作流；内部服务已通过实际项目保存和恢复验证。旧独立项目及旧单项目多集入口维持原语义，没有被自动拆分、重编号或复制素材。

PostgreSQL 部署时须先备份并停止 API/worker，再按既有离线迁移器 `store-migrate --mode init --confirm-stopped` 创建新表和 `studio_series_episode_project` 外键。迁移后需按现有部署约定核对运行角色对新表的DML权限。readiness 在表或外键缺失时失败，不在启动时自动改库。本轮只操作一次性测试 schema/数据库。文件模式新目录自动建立；备份/恢复须包含整个 DATA_DIR 内 series 目录以及原核心数据。
