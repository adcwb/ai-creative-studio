# 实施记录：持久分段渲染与继续合成

日期：2026-11-05。开发基线：`0a07702190cffa11cc2e11c53af43fc6cace4bfa`。状态：T06核心实现与专项已落地，最终完整回归结果见下；整体规格仍为Implementing。此阶段不推送、部署、操作生产库或调用真实收费模型。对应FR-R3、AC-R01/03/04/05及AC-O02/08。

## 创作者流程

导演确认当前剪辑后点击原有“合成并导出MP4”。导出固定当时的时间轴、素材身份和内容摘要，不因后续修改当前剪辑而悄悄改变本次成片。普通镜头显示画面与声音的分段进度，随后显示整理成片；无需停留在页面。版式、字体、深绿/白色和按钮沿用现有设计，没有另建制作导航或模型价格确认。

新导出在服务重启后自动继续已有检查点。失败或取消后，允许明确点击“继续合成”，沿用同一个导出和原时间轴，不重新提交图像/视频/文本模型。若想使用后来修改的剪辑，应新建导出。素材或编码环境已变化时明确要求重新导出，不把旧结果冒充新版本。旧版未完成导出仍保留原先失败策略，既有成功成片不重编码、不改ID。

取消立即撤销结果发布资格；已经开始的私有文件写入可能留下孤儿字节，但不会成为可下载的成功成片。存储或编码失败保留进度供人工恢复后继续；当前没有承诺自动判断磁盘恢复或无限次自动重试。

## 时间与渲染合同

- [纯时间计划](../../../../backend/internal/modules/media/render.go)将十进制时长以有理数相加，只在全局边界量化为24fps整数帧，音频采用48kHz，每帧对应2000采样。不是逐镜四舍五入再累计。段计划惰性遍历，不在接受任务时为整个长片逐帧分配对象。
- 每镜保留不重叠core区间；交叉淡化/擦除/滑动/圆形转场单独拥有左右handle对应的输出区间。core拆为默认十秒的段，转场不重复扣时，也不重复输出边界帧。旧逐次重编码整段前缀的pairwise合并代码已删除。
- [分段执行](../../../../backend/internal/application/render_segments.go)将画面和PCM分别保存。各视频段统一输出尺寸、24fps、SAR和yuv420p；画面叠层按顺序以两输入执行，关键帧使用全局时钟，跨段不会重启动画。烧录字幕按全局cue裁剪到本段，软字幕最终一次封装。
- PCM使用整数采样裁剪、延迟与相交区间混音，保留原视频/独立原音来源。转场采用显式逐采样淡出/淡入后混音，绕过本机FFmpeg在等长acrossfade输入上的单采样输出问题。附加音轨、背景音乐和叠层原音在缩短后的全局时间轴处理。连续PCM最终只编码一次AAC，避免逐段AAC priming反复累积。
- ffconcat的微秒时长按全局帧边界分配舍入余量，再转回视频1/24000时基；MP4 movie timescale为48000，使视频帧与音频采样均可精确表示。不能只验证容器文件存在或用宽松时长误差掩盖错帧。
- 每个新产物先检查真实codec、像素、帧率/帧数、声道/采样率/采样区间，并完整解码、计算整文件SHA，再接受检查点。最终MP4完整验证且原子写入，正式成功状态与PG队列完成同事务提交。字幕附属文件也保留原下载地址。

`MEDIA_RENDER_SEGMENT_SECONDS`为部署端1–30的整数，默认10；控制单次编码工作量，不限制作品总时长。已有manifest固定自己的段尺寸，修改部署参数不会重切已经接受的任务。服务启动检查非法配置。每个编码/解码命令保留原有五分钟运行时限，后台worker续租；整部电影不受“4K十五秒”等产品时长配额约束。

## 持久化与并发

[检查点适配器](../../../../backend/internal/application/render_checkpoint.go)固定manifest的空间/项目/导出、原始时间轴、源SHA、整数计划、段尺寸、算法版本与FFmpeg/ffprobe版本指纹。每个artifact记录manifest hash、步骤、全局帧区间、类型、大小和输出SHA。

文件模式使用`media/render-checkpoints/<owner-hash>`，manifest与每步骤独立JSON、fsync/原子rename，跨进程flock串行化同一导出。PG使用独立的`studio_render_checkpoints`索引表，不放入旧media整体scope。manifest/段/产物是该表中不同的步骤记录，未采用提案里的三张独立表。具体checkpoint事务短小，网络和FFmpeg执行不占用SQL事务；每次提交验证当前队列租约。原始素材仍走现有媒体存储边界。

产物先以`staging`保存稳定身份，再转存共享blob并改为`ready`。即使对象已接受而响应丢失，进程重启后也能用同一产物和S3上传身份继续，避免重新编码和换key。只有ready表示共享存储已确认；另一worker遇到仅在旧机器的未确认临时产物可以重做这一未接受步骤。正确的ready产物按完整SHA复用，缺失或损坏才重做/恢复，不因扩展名相同就信任。旧租约可能留下不可见孤儿对象，无权接受检查点或发布成片。

[本地队列](../../../../backend/internal/application/media_render.go)按持久导出恢复，尝试身份防止旧取消任务回写新尝试；[PG worker](../../../../backend/internal/application/queued_export_worker.go)修复了独立原音来源的素材恢复，并在运行时展示状态。只有`kind=export`且payload标记`render_version=1`的过期本地合成可自动接管。真实模型、旧版导出和已取消任务不会被此规则自动重放。现有导出worker内顺序执行分段，不宣称已经有分布式逐段DAG或长期公平调度。

## API、权限与升级

新增`POST /api/v1/projects/{id}/media/exports/{export_id}/resume`，空对象输入、原幂等键重放，返回202及原导出。不同请求键遇到已排队/运行任务也不会再排第二个执行。仅本地协议版本可继续；原始snapshot不可替换。MediaExport增加只读`render_version`、`render_progress`和`resume_available`，旧记录缺省兼容。见[OpenAPI](../../../../api/openapi.json)及[恢复入口](../../../../backend/internal/application/media_render_resume.go)。

沿用当前项目成员/写角色、CSRF和租户隔离。成员撤销后不能借旧回执继续；没有越过网关能力、凭据或内容审核，也没有恢复预算/报价门槛。后端错误不给出私有路径、对象地址或供应商响应；界面提供本地化的可恢复/重新导出提示。

新增PG表必须先停API/worker、备份，在副本演练后用同版本`store-migrate --mode init --confirm-stopped`离线初始化，核对运行角色新表DML权限，再启动。没有在线DDL或生产迁移。新readiness要求具体checkpoint列。

文件↔PG导入导出已经注册，验证manifest、步骤hash、帧区间、归属与来源身份；文件源不被改写。离线blob迁移包含ready检查点，允许新版本中断任务继续迁移，旧版未解决导出仍拒绝。PG缓存若含本机文件检查点会拒绝忽略。元数据导出创建完整的空results目录，以便后续显式恢复二进制；不能把导出JSON当作已经复制媒体。原生PG备份包括新增表，blob备份沿用已有不可变对象清单。

## 剩余边界

支持的是当前SDR、H.264/yuv420p、24fps和48kHz双声道交付；没有承诺HDR、电影调色/色彩管理、原生模型4K、AI超分或真实艺术效果。输出像素与源画质分开说明。独立真实S3及付费模型仍未验证，本地S3协议夹具不能证明生产服务兼容。

当前保守保留分段PCM、全局PCM和最终产物，会增加暂存/对象占用；不以产品容量配额解决这一问题。旧media/creative等整体scope尚未全部拆分，长期检查点/孤儿对象GC、冷归档、统一资源恢复调度仍属T03/T51–T52；目前保守保留检查点，不按数量删除作品。分段仍在一个导出worker内顺序执行；P4制作DAG尚未实现。系列/季/集、旧多集拆分、连续性、编剧与导演工作台以及200集容量仍未交付，不能因本阶段恢复成功提前推送。
