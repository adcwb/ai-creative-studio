# 旧多集项目分集复制实施记录

日期：2026-11-05。开发基线：本地 `6146d4fc35fffecdeac80caf73f3aed2d4f82c8e`。接续[T32A稳定身份](structure-implementation.md)。本阶段实现T32B–T32D；完整Spec仍在实施，T33连续性、编剧工作台、导演与制作编排、全流程200集容量并未交付。完成整个Spec并验证前不推送、不部署、不操作生产数据或真实收费模型。

## 创作者流程与行为

在旧短剧“项目总览”的“将旧项目分集复制到系列”展开工具，选择原集、目标系列/季与目标集号。先预览，再确认复制一集，成功后打开独立剧集继续制作。第7/120集在目标项目内统一为本地第1集，外部系列集号仍显示7/120；后续集号移动与导出沿用T31的不可变导出上下文。

新工具沿用已有panel、按钮、输入框、editing-note与配色变量；桌面双栏、手机单栏。提供空状态、源读取错误、预览问题、复制进度、停止与刷新恢复。源项目有未保存编辑时先保存，避免把屏幕草稿误当作服务端迁移来源。普通只读成员可以查看已完成结果，不能预览确认或推进写操作。

归属不明的独立镜头或已删除场次关联镜头必须明确选择“复制到本集”或“留在原项目”，不按相邻镜头猜测。无法取得旧分镜来源稿时可以显式选择分镜留在原项目；目标时间轴解除旧镜头关联，但保留实际媒体与剪辑。角色素材优先稳定ID；旧名字只有唯一可证映射时才能复用，歧义或失效ID要求明确选择角色或解除角色关联。

迁移是保留原稿的复制，不是破坏性转换：源项目正文、原始历史、媒体、旧成片与原入口不变。目标复制选中集的场次/镜头、所需媒体、当前角色参考、选片/审片记录、剪辑时码/裁切/音轨/字幕及精确版本的素材库绑定。目标角色/场次沿用确定的来源ID，但资产ID、拥有者和文件路径独立，来源记录不授予权限。

旧发布令牌、账号连接、发布任务、活动生成/导出/识别任务、海报和提示词应用记录不复制；原始历史及这些记录继续留在原项目。素材库版本绑定保留，不能把它误报为复制了全部生成来源任务。已有ASR/估算字幕的文本与时码可保留为`imported`，原类型/任务ID记在迁移清单中，目标不冒充完成过识别或沿用旧任务授权。手工字幕继续标记为manual。

输出选择“使用预览时的系列设置”或“保留旧剪辑清晰度与画幅”。这只决定后期设置，不改变已复制源文件像素，不自动生成或升采样，也不声称验证了原生4K模型质量。迁移无报价、成本预留或项目额度检查，不调用模型。每次只处理一个持久步骤；HTTP同时进行的本地媒体复制/探测采用两个工作槽等待，不以项目素材或集数配额拒绝任务。

## 代码与合同

- `backend/internal/modules/seriesmigration/{model,job}.go`：纯计划编译、归属校验、确定性ID、源指纹、计划摘要、持久状态与字节证明。模块只依赖projects/media/series领域合同；架构测试显式登记该边，继续禁止基础设施/SDK和反向业务依赖。
- `backend/internal/persistence/migrationrepo/`：每集独立文件实体或`studio_episode_migrations`行、不可变计划、CAS检查点、空间/原项目隔离、分页；文件fsync+rename+flock，PG每任务session advisory lock与短事务同步提交/离线迁移屏障。复制期间不持有长SQL事务。
- `backend/internal/persistence/seriesrepo/preparation.go`：稳定目标身份、隐藏preparing目录、编号预留、验证后可见、停止释放编号。普通启动恢复不得将迁移准备态自动公开。文件使用不可见cancelled墓碑；PG准备节点停止时删除。
- `backend/internal/application/episode_migration*.go`：只读源快照、已接受请求重放、每步当前权限、流式复制与SHA-256、音视频实际探测、目标引用重写、最终源/目标字节对账、崩溃收尾与停止。保留源的旧nil/空数组表示，迁移不顺带规范化原稿。
- `frontend/src/features/projects/EpisodeMigrationPanel.tsx`：C端预览、选择、确认、步骤续跑、列表摘要与恢复；复用`useSeriesWrite`保留未知创建的原nonce/body。列表不传完整剧本/计划或逐文件摘要。
- `api/openapi.json`与`scripts/{contract_check,secure_contract_check}.py`：真实HTTP响应、错误和权限合同。

新增项目HTTP（都在现有认证、组织权限和CSRF之内）：

| 方法/路径（省略`/api/v1`） | 行为 |
| --- | --- |
| GET `/projects/{id}/migration-source` | 只读版本、原集、稳定角色和待选择镜头 |
| POST `/projects/{id}/episode-migration-preview` | 只读编译计划、问题、来源摘要与目标输出 |
| GET/POST `/projects/{id}/episode-migrations` | 摘要分页/接受不可变计划，创建键绑定空间和用户 |
| GET `/projects/{id}/episode-migrations/{migration_id}` | 当前详细计划与证明 |
| POST `…/{migration_id}/continue` | 预留/复制单份素材/最终对账并公开之一 |
| POST `…/{migration_id}/cancel` | 停止尚未公开目标并清理逻辑元数据 |

创建需要原项目/媒体/季版本与预览摘要；同键不同原请求返回冲突。已接受创建在来源后来变更后仍返回原任务，绝不新建另一目标。步骤按`expected_version`与任务检查点幂等：旧版本只返回现状，不多做下一步；未来版本冲突。任务详情和执行都重新验证当前空间权限，不能用`created_by`或来源JSON冒充会话。

## 恢复、对账与存储切换

流程：accepted → preparing → copying（每素材一次持久证明）→ validating → completed；错误保留paused与原阶段。cancelling作为持久意图，暂停、重启、重复请求后仍继续停止，不重新开始复制。

目标ID和目标资产ID由任务及来源确定。复制通过当前授权的源blob键读取，不信任记录中的URL，不跟随本地符号链接。数据流经64KiB缓冲写临时文件并计算摘要，探测类型与时长；已存在的目标文件必须摘要/长度一致，元数据重复只确认同一记录。BlobStore配置下写入目标自己的对象键，另一个API使用独立缓存仍能接续。最终公开前重新核对源/目标每份文件的SHA和长度、元数据版本、场次/镜头/时间轴引用和数量。

文件模式通过“持久准备标记→目标内容→公开标记”的恢复协议避免半成品可见；PG的目录与目标Project创建/公开共用core事务，媒体提交后才公开。若进程死在公开成功但任务收尾前，恢复首先识别ready目录，仅补任务完成标记，不能覆盖已被用户编辑的目标。源被编辑、目标目录被归档、权限撤销或文件损坏均不会静默采纳新版本。

停止只删除该任务拥有的未公开目标Project/历史/媒体元数据，释放编号；不删除源，不删除已经公开的目标。**已经落盘的不可变blob可能成为孤儿，本阶段不做物理GC**；不能将“未完成目标已移除”理解为磁盘字节立刻回收。后续T03/T52生命周期清理应从仍有引用的对象、未知结果和保留期出发清理，不能按任务失败直接删共享或可能已公开对象。准备中的目录会暂时阻止相同季的重排；完成或停止后恢复，属于一致性协调而非用户配额。

新表与索引注册到显式PG初始化/迁移及readiness。运行服务仍不自动做DDL。文件→PG、PG→文件的离线工具复制完整迁移任务/证明和隐藏准备目录，验证副本也包含这些记录；媒体二进制仍按既有离线复制/对象存储合同迁移，不在JSON中装入blob。PG打开含本地迁移记录的缓存目录会拒绝，要求离线迁移和新缓存，不默默丢弃检查点。

回退方式：未完成任务停止后重新预览；完成目标继续独立编辑，也可返回保留的原项目。不能用旧二进制读取新`migration_source`、`character_id`、imported字幕或新目录状态后直接覆盖数据；软件回滚前恢复匹配的备份或验证兼容版本。离线切换必须先停止写入和worker；本轮没有执行生产切换。
