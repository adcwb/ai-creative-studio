# 真实网关文本输入窗口适配实施记录

日期：2026-11-05。代码基线：`6743c5a950600d9dd06728490554e9e300f09655`。T33B4 的 Responses 原生计数适配已实现并通过本阶段最终回归。整套 Spec、风格/声音授权、实际图像视频资产适配、编剧导演及制作编排、200 集完整制作容量仍未完成；此前不推送、不部署。

## 创作与配置合同

这不是项目额度功能。现有已启用、能力匹配的 Chat Completions 模型继续直接使用，不必补填窗口、分词、计数、价格或预算。容量未知时不把字节数冒充 token，不按模型名字猜分词器；上游明确返回输入窗口错误时展示安全提示，不自动截稿或回退到其他接口/模拟结果。

仅当管理员已核实网关支持相应协议，才在模型管理选择 Responses；额外确认原生输入计数能力并填写上游真实总窗口后，才启用计数预检。不要仅为获得计数而把只支持 Chat 的模型改为 Responses。输入能力是模型声明，不能代替上游验证，也不是项目可用次数/费用的上限。

| 配置 | 实际行为 |
| --- | --- |
| 旧配置/Chat Completions | 保留 `/chat/completions`；不发原生计数请求，不捏造 token 数；上游负责真实窗口 |
| Responses、未启用计数 | 同步 `/responses`；声明的窗口不产生猜测式本地拦截，上游负责真实窗口 |
| Responses、已确认原生计数 | 先 `/responses/input_tokens`，计数全部输入与外围指引/输出格式；本次计数加配置的最大输出预留必须能装入声明窗口，再发送生成 |
| 计数不支持/失败/非法 | 这次任务失败，没有生成 POST；不降级到 Chat，不绕过计数继续生成 |
| 原生或上游明确窗口不足 | 明确报告，保留来源快照与正式稿；创作者减少本次资料或选择更合适的模型后发起新的意图，不静默修改旧请求 |

## 实际实现

- `application/gateway_models.go`：可选 `text_protocol`、`context_window_tokens`、`native_input_counting`，默认仍是旧 Chat 行为；计数声明只能用于 Responses/text，真实窗口必须能保留配置的输出。模型保存/CAS/重启保留这些字段；目录同步不会覆盖它们。没有新增凭据或费用字段，没有新 PG 表/DDL。
- `application/gateway_runtime.go`：只在当前组织/成员、网关/模型/功能绑定及审核允许的执行中创建适配器，使用已选配置版本和原网关的受控客户端/加密凭据。计数和生成都经过现有目标地址、权限和版本再验，不另开外部目标或放宽恢复权限。
- `application/provider_responses.go`：纯文本 JSON 创作使用独立协议；计数与生成的 model、instructions、input、text、tools/tool_choice 相同，明确禁用自动截断，保留完整选中资料。生成发送 `max_output_tokens`、`store:false`、`background:false`、`stream:false`，禁用工具；只接收完成的一份助手 JSON，忽略私有 reasoning，不把拒绝/不完整结果当成功。
- 原生计数是上游返回的整数，不运行臆测的本地分词换算。最大输出始终按模型配置预留；数据类型、范围、空/负/缺失计数及传输工作集都校验。计数成功也不是永久派发许可。
- `application/provider_creative.go`：既有 Chat JSON 协议保持；识别文本接口有限 4xx 错误包中的明确容量代码，安全展示 `provider_input_capacity`，不回显上游原文。无法完成计数时使用 `provider_input_count_unavailable`。原请求/原结果重放不重新计数或再生成。
- 文本协议覆盖创意分析、剧本、分镜规划与故事连续性检查的共享 JSON 路径；图像、视频、语音、视觉理解仍沿用各自已有适配器。本阶段不能冒充多模态原生计数或原生人物/声音控制。

## 计数期间变化与恢复

`story_check_worker.go` 将可信来源核验传给文本适配器：计数前核对当前快照，计数完成后、真正生成前再验目录/剧本/正式资料。计数期间改稿时停止生成；旧快照和正式稿不变，不用新稿偷偷替代原请求。

`jobqueue.WithLeaseFence/CheckContextLease` 将 worker 的租约信息放在服务端上下文中；文本生成前读取当前 token/state/有效期。源读取和租约检查均不持有跨网络的事务或行锁。仍必须执行既有 Dispatch，最终结果仍用事务围栏提交；该读取不能代替它们。生成前重新核验时已生效的权限撤销、配置变化、取消或租约失效将阻止后续生成。这是派发前的时点核验，不是跨网络的永久锁定；既有心跳和最终结果围栏仍必须执行。

既有派发意图在适配器调用前持久化，因此计数期间发生进程丢失仍保守归 unknown，不自动重发；不能仅凭没有拿到生成结果断言上游没有执行。PG 的领取/过期处理先确定 unknown，应用 reconciler 再同步领域状态，旧租约不能提交。对外原请求恢复只返回原任务。HTTP 调用统计包含原生计数请求，不能将请求数直接解释为生成次数或费用；项目不据此恢复预算/额度门槛。

## 兼容与边界

OpenAPI、模型管理表单、错误显示、实际 HTTP/网关测试同步。新字段是可选的，旧数据不需要补填；新数据与软件版本应匹配回退，不把旧二进制直接回写新配置当作已验证的回滚。整体版本上线仍需此前各阶段的匹配迁移与备份；本轮不执行生产操作。

原有 2 MiB 资料工作集与单请求传输边界仍是明确的运行保护，不能据此保证任意模型窗口足够。未支持的 Chat 原生计数、真实供应商窗口/计费和艺术效果没有通过本地合成测试获证。窗口为管理员根据上游声明配置；本项目没有能力替上游证明其分词或声明容量正确。预检不改动纳入/省略清单和摘要；不自动丢弃必需资料，也不为成功而隐藏检索范围。

原生协议核对：[输入 token 计数](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count)、[Responses 创建合同](https://developers.openai.com/api/reference/resources/responses/methods/create)。实现未依赖按模型名推断的 tokenizer，没有新增第三方运行依赖。
