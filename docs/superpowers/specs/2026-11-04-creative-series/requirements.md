## 1. 创作角色与目标

| 创作身份 | 核心判断由人负责 | AI 提供的辅助 | 系统应保存的成果 |
| --- | --- | --- | --- |
| 设计师 / 美术指导 | 受众、视觉概念、参考选择、色彩/构图规则、最终风格 | 提示词变体、候选图、参考差异建议 | 情绪板、可复用配方、风格版本、采用理由 |
| 编剧 / 总编剧 | 主题、人物欲望与弱点、主线、季弧、冲突和结局、何时揭示事实 | 集纲候选、对白变体、伏笔和连续性检查 | 世界观圣经、人物弧线、分季/分集结构、正式事实与修订 |
| 导演 / 分镜师 | 一场戏要观众感到什么、表演、轴线、视点、节奏、声画关系 | 镜头拆解、构图候选、静帧预演、镜间差异检查 | 场面意图、镜头表、动态分镜、选片与返修决定 |
| 剪辑 / 声音设计 | 取舍、停顿、反应镜、声画先后、音乐情绪、混音和成片 | 对齐、转写、技术质检与候选声音 | 时间轴、声音版本、审片意见、封版交付清单 |
| 制片 / 协作者 | 优先集段、负责人、资源安排、交付顺序 | 进度聚合、阻塞定位、依赖影响分析 | 制作排期、状态、负责人、可续跑任务与版本证据 |

同一个人可以承担所有角色；角色是界面视角，不能自动授予系统管理员权限。单人不应被强迫走多级审批。组织协作沿用现有可编辑成员权限，新增审核责任只在明确设置的项目流程内生效。

## 3. 功能合同

### 3.1 提示词创作配方

- **FR-P1 MUST**：允许有编辑权的用户创建、编辑、复制、归档自定义图像模板；从编辑器或成功结果保存时先打开可编辑配方草稿。保存、编译预览、选用和恢复版本均不触发模型调用。系统内置模板只读，可以复制为自定义模板。
- **FR-P2 MUST**：模板有稳定 ID、名称、简述、正文、类别/标签、默认创作参数、所有者、可见性和不可变版本。更新用预期版本，冲突保留草稿；归档不破坏历史任务和已保存版本。
- **FR-P3 MUST**：默认个人可见；可显式共享到当前组织。个人模板仅所有者可读写，组织模板当前成员可读、有编辑权者可改；管理员可进行经审计的归档管理，但不是无痕读取私人正文的后门。拥有跨组织成员身份不产生跨空间共享。公开模板市场不在范围内。
- **FR-P4 MUST**：支持按名称/正文的简单文本搜索、类别、标签、来源、归档状态筛选及稳定游标分页。用户正文原样保存和展示，不当作i18n key、HTML或代码执行。个人收藏只影响自己的列表，不修改团队模板。类别/标签是纯文本、受请求解析预算保护但不设累计条数配额；首版不引入复杂分类管理系统。
- **FR-P5 MUST**：P2 支持 `{{variable_name}}` 简单占位符，变量仅 text/enum、必填/默认值/字数上限；无表达式、循环、网络取值、脚本、密钥或隐藏系统指令。服务端编译并验证展开后 3–1000 字与目录参数；未知/缺失变量、长度超限给出字段错误，不能截断或发送半成品。
- **FR-P6 MUST**：任务保存源模板版本、变量值、展开文本摘要、最终有效参数及参考资产版本快照；旧任务重试复用旧输入，不能自动跟随模板最新版。修改后生成是新任务，源关联仍可查询。
- **FR-P7 MUST**：参考配方明确参考用途和版本；只在支持该类引用的项目制作入口启用。模型能力或参考组合不满足时展示具体原因，可由用户主动改选或显式去掉引用，不能静默忽略。纯文本模板也能在首页使用。模型选择由当前组织功能绑定决定，模板不能携带凭据、任意地址或覆盖授权。

### 3.2 系列、剧作与连续性

- **FR-S1 MUST**：系列—季—集为独立实体，有稳定 ID、可重排显示序号、标题、目标时长和阶段；可持续管理100–200集并继续新增，不设集数配额。新系列每集独立关联 Project，列表分页，不一次加载全季剧本和素材。旧独立项目和已有多集项目继续可读写，旧120集存储与999集编号限制须迁移，不能让旧入口保留额度门槛。
- **FR-S2 MUST**：世界观包含正式事实、规则、禁改项、人物目标/关系、季弧、集纲和伏笔回收计划。事实注明故事时间、生效集段、叙述顺序与“谁知道什么”；可区分闪回、主观误认、未证实信息和真实设定。AI 建议与正式事实分开，采纳需要明确动作与版本。
- **FR-S3 MUST**：剧本按集编辑/生成，场景和角色引用稳定 ID；导演镜头绑定 scene_id，不受插入、重排或重命名影响。模型输出先结构校验，候选不覆盖当前有效剧本。单次生成不能以整季全文作默认上下文。
- **FR-S4 MUST**：生成上下文包含固定版本的世界/人物资料、当前集纲、相关前集已确认事件、待回收伏笔与本集边界；展示缺失/冲突/超长项目。缩减上下文需可解释，不可静默丢弃禁改项。上下文摘要是带来源版本的派生资料，不是真相源。
- **FR-S5 MUST**：人物外观、服装状态、场景、道具、风格、声音版本可跨集复用。变更须显示哪些未完成集/已完成镜头需复查；旧成片不自动换脸换声或重生成。视觉检查只提出证据与不确定性，不能宣称身份一致已被算法保证。

### 3.3 导演、制作与交付

- **FR-D1 MUST**：场面意图和镜头字段包含叙事目的、角色表演、景别/角度/构图、轴线/朝向、运动意图、时长/节奏、对白/声音意图。适配器逐项区分 native/reference/prompt_only/unsupported；提示词描述不包装成精确摄影控制。
- **FR-D2 MUST**：支持静帧、字幕、临时声轨的动态分镜，明确标为预演。人物定稿、剧本定稿、预演和成片采用是不同艺术决定；可以修改和重开，不把生成完成等同于采纳。
- **FR-D3 MUST**：复用候选比较与采用、素材时间点批注/负责人/优先级；扩展为镜头/集级审片与返修状态。采用素材不自动覆盖剪辑；进入时间轴需明确应用动作与版本检查。未解决的高优先级批注默认警示；是否强制阻止封版由项目明示流程决定，普通生成不增加审批门槛。
- **FR-D4 MUST**：一次改稿产生依赖影响清单；明确区分内容已过期、建议复查、未受影响。仅用户选择后创建受影响节点的新 attempt，旧素材和采用记录保持可追溯。
- **FR-O1 MUST**：批量制作先选择集/镜头、阶段、模型和候选数，展示节点数量、输入版本、资源状态和失败策略；用户启动一次即可，不报价不询价。默认每节点 1 候选，可调整为有限数。禁止保存模板或打开页面自动开跑。
- **FR-O2 MUST**：任务依赖、输入、模型配置版本、attempt 和回执持久化。暂停停止接新任务，取消阻止后续派发；已派发请求不可假装撤回。崩溃或结果未知不自动重发可能成功的 POST；只按供应商实际合同恢复查询，人工重试创建新 attempt 并保留旧不确定状态。
- **FR-O3 MUST**：200 集进度按阶段、负责人、阻塞原因分页汇总；失败可定位到集/场/镜/具体尝试。封版清单固定剧本、素材、声音、字幕、时间轴、渲染设置和审片决定。导出完成与社交平台发布分开，支持真实平台回执的 pending/unknown 状态。

### 3.4 时长、画质与后期

- **FR-R1 MUST**：每集目标时长60–120秒，各输出档均支持该完整时长；这是创作目标与验收区间，不是超出120秒就拒绝的账户额度。超目标只提示节奏/交付检查，确有平台或运行器不支持时返回具体能力原因，允许修改或拆分；不因选择4K而缩短成片。
- **FR-R2 MUST**：输出提供1K/2K/3K/4K档并显示准确像素，支持横屏/竖屏，方形输出另示具体像素。1K按产品标签映射1080p，不宣称行业统一定义。用户可选原生优先或允许后期放大；原生请求与最终渲染参数分别固定版本，源尺寸/实际输出/普通缩放或增强可追溯，不能把720p放大宣称原生4K。
- **FR-R3 MUST**：完整时间轴按帧/采样统一计时，按镜头和资源自动分段，可复用已完成段；跨段转场、字幕、音轨、叠层/关键帧和封面保持连续。移除总镜头/轨道/叠层的产品条数上限，以分批滤镜与混音执行。资源不足等待，进程重启从检查点续跑，不生成截断成片冒充成功。
- **FR-R4 MUST**：上传、下载、Blob、本地与对象存储、Range、媒体校验、备份恢复均支持超过128MiB的完整高清文件，正文与二进制分离且流式传输。保留单块请求/探测内存/文件类型/真实磁盘保护；不把128MiB换成另一累计或单作品商业配额。没有真实存储空间或不支持编码时报告资源/能力原因，不收费、不降低画质、不伪造结果。

### 3.5 去除项目额度

- **FR-Q1 MUST**：移除项目自设的累计素材、导出、剧集、场景/镜头、库资产/版本/绑定、审片/采用、数字人、任务/调用/回执数量及累计字节额度；不增加run最多20集或候选最多4个的新业务配额。分页、流式计划、实体存储、归档与去重保证持续使用，归档不是到期强删用户作品。
- **FR-Q2 MUST**：去除本地每小时生成/对齐/ASR等调用额度及任何实际预算预留门槛，网关承担余额、计量与配额管理。网关限流/余额不足原样语义脱敏展示，按明确合同等待或要求用户处理；不根据历史用量自行预判拒绝，也不自动绕过网关换模型。
- **FR-Q3 MUST**：CPU/GPU/磁盘/连接/解码内存/执行时间等部署能力属于运行调度；持久接受后排队，繁忙时等待不递减额度，不以queued+running总数封死入口。真实无法持久化时可明确503并允许同键恢复，绝不能返回已接受。鉴权、租户隔离、审核、授权撤销、幂等、上游真实能力与格式校验继续生效。

### 3.6 横切要求

- **NFR-01 MUST**：跨空间/跨项目访问、素材下载、引用、重放、批注和事件订阅都在服务端校验。成员撤销、模型禁用/改版和审核过期在实际派发前重新校验。日志不含凭据、私有正文或可复用下载令牌。
- **NFR-02 MUST**：数据库保存与入队在同一事务或受验证 outbox 内完成；写入使用版本比较和幂等键，相同键不同正文 409。多 API/worker 重复提交、崩溃与租约过期不造成已派发节点盲目重复执行。
- **NFR-03 MUST**：沿用无成本门槛并扩展为无项目配额：价格未填、零预算、旧预算耗尽、跨旧累计条数/小时次数/2GiB都不影响调用或编辑。保留独立审核、认证、调度和上游限流；每项阻塞明确来源，不把本地资源繁忙归类为网关预算不足。
- **NFR-04 MUST**：P5 前完成新域按租户/实体查询、热点 scope 拆分、任务/调用记录归档、素材生命周期和容量验收。归档不能删除恢复中的回执或已封版引用。200 集上线承诺以[容量验收](acceptance.md)为准。
- **NFR-05 MUST**：桌面三栏与手机单列流程可用、键盘可操作、状态有文本、未保存草稿切集提示；个人内容不被翻译函数误处理。不中断当前单图/单项目编辑入口。

## 4. 边界与非目标

首期不提供公开模板市场、跨组织分享、任意脚本变量、提示词自动购买、自动换模型、一次无人审看生成并发布整季、精确身份锁定、端到端 3D 动画或动作捕捉。不会默认删除其他内容审核策略，也不为本需求调用真实收费模型。是否增加真实视频适配器与声音克隆属于另外确认的供应商和授权范围。

不把“可创建 200 个集记录”当“能制作 200 集成片”；不把模型生成成功当艺术通过。单块传输、解析/解码、编码器与供应商真实能力继续校验，完整作品通过分片和流式处理消除旧产品限额，不能把“安全”作为保留旧30镜/15秒/128MiB拒绝的泛化理由。实际基础设施并非无限，详见设计第10节。

## 5. 产品假设与待决事项

以下明确区分已确认范围和仍可继续设计的默认值；关键未决项在相应阶段前解决。

| ID | 待决事项 | 推荐假设与影响 |
| --- | --- | --- |
| Q1 | 已确认时长/可选画质；画幅/平台待选 | 已确认每集约60–120秒、用户选1K–4K、无项目配额。推荐9:16；像素映射与原生/放大标识按设计第9节，无需再次询问用户是否要4K |
| Q2 | 漫剧表现形式 | 默认静帧/轻运动加配音，先验证叙事；高运动图生视频为可选镜头路径，需适配器和样片 |
| Q3 | 团队与模板默认权限 | 个人默认私有、显式组织共享；项目协作沿用 editor，单人采用即确认；需要组织级保密/审批再细化 |
| Q4 | 模型与资源环境 | 不预选品牌；分别绑定 text/image/video/tts/transcription/vision，缺一项只阻塞依赖它的节点 |
| Q5 | 内容来源和声音授权 | 用户自有/授权设定与参考；声音先使用有许可的现成 TTS；不默认开启克隆 |
| Q6 | 一季与生产节奏 | 支持多季且不设总集数配额；3集样片→20集试产→200集容量是验证阶段。允许用户主动选择整季排队，不强制拆成20集一单 |
| Q7 | 遗留多集项目迁移 | 旧入口可继续用；明确选择要拆的集后迁移，保留来源映射和原项目，不自动迁移所有历史 |

Ready前锁定P1字段/权限；P0A核定输出标签像素与基础设施能力，不能把已明确的时长、画质或去配额改回待授权。P3前确定Q2/Q6/Q7的创作/迁移取舍；收费样片仍须后续明确授权。本轮按依赖实现第一批基础能力，其他合同继续保持计划状态，具体见实施记录。
