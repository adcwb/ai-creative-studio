# 风格与声音意图卡、参考资料工作集实施记录

日期：2026-11-05。代码基线：`7c007e334d36c5de4c3fff7457b383ea4fdb7fc9`。当前为T33C2A：风格/声音意图卡、版本合同及移除旧参考数量判断已实现并通过阶段最终回归。**T33C2整体、可撤销使用授权、真实风格/声音/人物媒体派发适配、编剧导演/制作编排及完整200集制作容量仍未完成**；整套Spec完成并验证前不推送或部署。

## 创作者能做什么

在既有创作资产库中，按类型建立风格卡或声音卡，保存并比较不可变版本。风格卡记录色彩、线条、构图、光照与质感，支持项目中已有的有效参考图片；声音卡记录音色、表演情绪、语速停顿和发音。禁止变化项可按创作需要逐条添加，不再固定为20条。保存、改版、读取和原请求恢复不调用模型。

声音卡当前是表演意图，**不是可直接派发的voice ID、声音引用或克隆授权**。不提供假的音频上传/克隆按钮，不把图片当作声音参考，服务端也拒绝声音卡附加图片引用。风格卡的描述和参考当前也不自动注入模型。项目旧引用入口只列出其已经支持的角色/商品/场景，不把新卡片露成一个必然400的“可用”绑定选项；实际派发选择与授权仍由T33C2B/C实施。

页面复用既有资产库表单、历史、卡片与响应式布局，无新增设计系统/样式文件。两类意图卡使用专属空状态与能力说明，参考条目用次序和用途显示，不要求C端用户理解内部ID。历史参考图片延迟加载；保存不确定时沿用原请求恢复，不能编辑正文后偷偷换请求重试。

## 数据与API合同

`library.Card`增加可选`style`和`voice`，严格要求与kind一致且只有一种类型。style包含`palette/linework/composition/lighting/texture`；voice包含`timbre/performance/pace/pronunciation`。旧字段、资产/版本身份、SHA算法和原回执保持；两个新字段使用omitempty，旧卡片不被添加空对象或改写摘要。`character.voice_notes`仍为文字，不自动迁移成声音许可。

现有`/library/assets`及`/{assetId}/versions`写入、读取、列表和历史路线复用，kind增加style/voice；OpenAPI同步新字段、类型对应、声音意图的空媒体引用合同与413工作集错误。没有新增凭据、成本配置或供应商接口。

删除了HTTP、领域验证、编辑表单和OpenAPI中的每版本最多12份图片、最多20条禁止变化项，以及绑定返回结构的旧数量限制。**模型单次真实参考数量、图片类型/尺寸/字节与解码验证继续保留**；不得将“资产库能保存多份参考”理解为所有模型会同时使用它们。

单次写入仍沿用1 MiB HTTP解析边界，新增明确的1 MiB规范化版本元数据工作集；超过时返回`413/library_request_too_large`，不是项目资产、历史或累计容量配额。JSON转义也计入持久元数据，不能用少量入站文本制造无界文件记录。文件事务原有2 MiB记录保护继续保留；直接仓储调用、离线导入与实体读取也核验内容工作集，文件/PG语义一致。既有旧卡片的字段/12份参考/20条限制规模均在该工作集内。

浏览器恢复记录原来只接受64 KiB字符串，已与1 MiB入站工作集按UTF-8字节对齐。大于64 KiB、有效工作集内的原key/body可以完整恢复；跨空间/项目隔离和已知写入路径检查保留。

## 逐份准备与原子发布

`library_http.go`原先收集所有新图片的`[][]byte`再写；`library_binding.go`也同时读入全部参考后复制。移除12份限制不能保留这两个内存累积点。现在逐份验证、准备不可变Blob并释放本份字节，只保留有界元数据；绑定时也逐份再次核验字节长度/SHA，再复制与登记。复制路径接收请求上下文，取消后不发布部分元数据。

元数据/版本和回执仍在最终事务中提交。某份来源损坏、保存失败或取消时，不会出现半张资产卡或半套项目绑定；准备过的不可见Blob可能成为孤儿，不能因客户端未收到结果而擅自删除。原请求成功重放在新准备之前处理，防止重复绑定。安全孤儿清理和剩余scope/长任务调度仍属T03/T51等未退出任务；本阶段没有宣称内存峰值实测或无限大单次HTTP事务。

## PostgreSQL升级与回退

`studio_library_assets`的旧三类kind CHECK需经显式初始化迁移扩展为五类，命名为`studio_library_kind_v2`。初始化仅移除已知旧自动命名约束并幂等添加新约束，不改旧资产、版本与回执。常规readiness要求匹配的新约束，旧schema不能被新版本当作ready；readiness本身不做DDL。

上线时需按既有运维流程停止旧写入/worker、保留匹配备份，以迁移账号执行既有显式schema初始化，再启动匹配API/worker和前端。不要让旧二进制回写新卡片，或直接删除新kind字段来“回滚”；恢复匹配备份与二进制另行操作。本轮仅在隔离测试schema执行迁移，没有执行生产数据库操作、发布或部署。后续授权的停机初始化可复用既有`store-migrate -mode init -confirm-stopped`入口；本轮没有对生产执行此命令。
