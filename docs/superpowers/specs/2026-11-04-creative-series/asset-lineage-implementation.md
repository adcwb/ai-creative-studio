# 旧素材来源追溯与历史兼容实施记录

日期：2026-11-05。代码基线：`3c5abe39dafccc7e6b59d86f5b14de96a1bc0d8e`。对应T33C2C3，接续[当前使用声明与派发保护](asset-use-implementation.md)。本阶段补历史来源链，**没有把原生人物/风格/声音输入、C2D、编剧导演或制作编排标为完成**；完整Spec完成并验证前不推送。

## 创作工作流

创作者打开制作工作区，选中候选素材后可按需“查看素材来源”；素材与成片页面也提供同一入口。读取不会调用模型、改变文件、内容版本、回执或时间轴。页面区分“已有来源记录”“从原始记录追溯”“尚无法核对”，不把来源记录说成权利证明或锁脸/音色质量认证。

无法追溯的旧图片/视频仍可查看、下载、选片、剪辑与本地合成，也能经既有分集迁移复制；不会删除旧作品。但不能把它用于新的CreativeJob创作模型输入，或另建卡片把不明来源包装成明确许可。创作者可恢复匹配的原记录，或从有明确来源的素材重新制作。没有凭名称、当前海报文档或人工勾选一个“可信”按钮补造历史。

来源核对只在点击后发生，没有为每个候选自动扫描。加载、错误与重读位于对应素材旁，切换素材/项目或离开时取消读取；沿用现有按钮、正文与响应式布局，不新增一套视觉风格。

## 可信证据与判定

`application/library_lineage.go`把来源解析与`library_dispatch.go`中的当前授权检查分开。追溯不会授予权限；新请求仍固定当前声明修订，并在真实派发前再次核验。

| 记录 | 使用的证据 | 不做的推断 |
| --- | --- | --- |
| 已保存来源的新素材 | 服务端完整来源标记、固定库版本/父素材、原始字节SHA | 不把标记当法律证明或供应商验证 |
| 旧库绑定/提示词应用 | 服务端绑定或应用、确切版本/参考ID、参考字节摘要 | 不靠显示Source或同名匹配 |
| 旧创作结果 | 同空间、同项目任务；准确`creative-{jobId}`入库回执和素材身份；任务固定的参考/首尾帧/运动/蒙版/音频/对照输入 | 不选“最近一次任务”，不按镜头或名称猜测；缺回执/矛盾声明不通过 |
| 入库完成但任务收尾丢失 | 入库回执中的确切asset ID，即使任务asset_id仍为空 | 不重新发送生成POST |
| 旧分集复制 | 目标项目不可变迁移来源、封存计划、准确来源→目标ID、逐素材SHA证明 | 不依赖仍存在的源缓存，不把裁剪后的绑定数组下标当原参考序号 |
| 旧转换/海报无输入日志 | 无法恢复准确输入，状态为unverifiable | 不用当前海报内容、文件名或相似像素补造来源 |

旧创作结果的原始上传回执摘要使用JSON-base64字节语义。新解析在**同一次流式读取**中计算原始SHA和旧回执摘要，避免两次读到不同内容；只接受精确回执匹配。服务端原始任务中的稳定身份是来源证据，用户可编辑的显示名称只参与原回执摘要核对，不能单独决定来源。其他空间/项目任务不参与判定，冲突任务不采用“新记录优先”。

同一请求对来源图和媒体元数据做记忆化；共享祖先不被指数重复展开，环路受控拒绝。字节核验为流式，祖先只恢复可信元数据，不要求重新下载已经有独立复制证明的旧源文件。当前选中的实际派发文件仍核验字节身份。此项没有改写旧模型的真实请求捕获，不能据此认证历史模型确实使用了某张图或保证艺术质量。

## 库版本不能切断旧来源

历史图片可能已经被再次存入另一张库卡。仅追溯任务结果不足以防止切断撤销关系，因此旧`library.Reference`还会沿服务端保存的`source_project_id/source_asset_id`追溯。缺原记录不是新的许可根；另建卡片的声明不能替代仍需核验的祖先声明。

新库参考增加可选`provenance_version:1`，表示完整继承范围已由服务端固定；没有祖先库引用也会明确记录此格式。旧字段缺省为0，原有JSON与内容摘要不新增空字段。旧参考只读动态恢复；保存**新版本**时才固定恢复结果，原版本、摘要、参考文件和原回执不改写。当前来源状态并不自动包含未来内容版本，也不替换现行授权范围。

复制旧库版本或应用旧配方时，先准备来源计划，再逐份验证/复制实际参考字节。可追溯的范围写入新副本；不明来源副本保留不明标记供历史使用，不能在复制时被变成新的许可根。旧迁移的绑定可能只保留原参考中的一部分，使用封存SHA证明匹配原版本参考；不使用目标绑定中已变化的数组位置。

## 数据与接口

`media.MediaAsset`增加可选`provenance_version:1`及`provenance_unknown:true`，复用固定`library_sources/parent_asset_ids/content_sha256`。新上传、创作结果、转换、海报、库/配方复制、演示测试设施和迁移由服务端记录，不开放客户端改写这些字段。旧记录仍可读取。未知来源经迁移继续保留未知状态及目标独立字节SHA，不能通过迁移“洗掉”状态。

新增只读接口：

`GET /api/v1/projects/{id}/media/assets/{assetId}/lineage?space_id=...`

响应为`asset_id/status(recorded|recovered|unverifiable)/library_sources`和可用的`content_sha256`。recovered表示依据原记录计算出的来源，**不表示旧文件已经被改写**。读取失败用专属503说明原文件未修改、可重读/恢复匹配记录；GET不要求写入幂等键。匿名、非当前成员和跨空间拒绝，同空间viewer可读取。

单进程最多两个来源核对工作槽，其余请求等待并可取消；没有拒绝用户继续持有或新增资产，也不是项目次数、历史或容量配额。正常创作任务使用既有任务调度，不增加成本/预算配置。当前CreativeJob派发或新库根遇到unverifiable返回409明确错误；现有历史文件读取与本地剪辑继续可用。

PostgreSQL仍复用既有媒体/创作/库版本JSON与迁移实体，无新增DDL或自动生产迁移。停旧写入者、保留匹配备份并升级匹配前后端/worker的要求继续适用；旧二进制不能在新数据上混写或直接回退。

## 明确边界与下一阶段

“不可追溯”是明确的产品状态，不能声称已经认证所有历史像素的真实来源。外部下载再上传的素材无法仅从像素证明其权利，系统也不认证法律声明。读取和备份中的旧内容保留，不对不明来源自动发送付费重生成。

消费者覆盖仍需C2D补齐：本轮接入CreativeJob与库/配方根，`alignment_store.go`的`CreateAlignment/runTask`、`alignment_http.go`仍走独立音频任务，需要增加对应来源pin、当前授权用途与真实派发检查；不能把本阶段的CreativeJob用例说成ASR/对齐等全部入口已经覆盖。后续新增原生音色/声音媒体输入也必须纳入这一矩阵，避免读分析用途和克隆用途混淆。

本阶段没有解决媒体/创作全scope快照的其余规模瓶颈，不能把请求内缓存宣称为200集生产容量验收；该项仍归P0A/P5。真实S3/供应商效果、原生4K、Docker/云端CI与完整200集生产不作为本阶段验证结果。

下一项T33C2C2必须接上明确版本和用途的本集人物/风格/声音选择，并展示`native/reference/prompt_only/unsupported`的实际合同。代码已存在`ModelRequest.Voice`与网关speech的原生voice字段，但声音意图卡没有原生preset或音频引用配置；不能把表演说明拼进朗读文本，或仅保存voice notes便声称完成。人物图片引用是条件引导，不代表原生锁脸；风格文字或参考不能伪装成原生风格ID。完整C2D退出后再推进T34编剧、T41–T45导演与制作编排，最后做完整容量和发布核验。

后续T33C2D1按[音频消费来源记录](alignment-source-implementation.md)补上独立ASR/转写/强制对齐消费链的来源固定与派发检查，本文保留C2C3当时范围。原生人物/风格/声音选择及C2D完整集成仍未完成。
