状态：本地阶段实现，未推送，完整 N1/N2 规格尚未完成。[验证结果](validation.md)。起点为本地 `fb36aca`，其功能基线为已发布 `486ef47`。不能用上一阶段的云端 CI 结果证明本轮代码已通过云端检查。

## 用户可实际操作的闭环

从左栏“创作流程”进入已有作品；新建的图像作品也可直接进入。可选择真实步骤模板，拖动节点、缩放、连接或在手机/键盘步骤列表选择来源；撤销/重做当前图编辑；保存、重新载入不可变修订。没有任意脚本、URL 或 shell 执行节点。

首批节点为**描述与文案常量、当前项目素材、图像生成、配音生成、视频生成、人工选择、输出素材**。文本常量不冒充 LLM 文本处理。模型步骤必须选择组织真实网关及匹配模型/功能绑定；普通文本模型不能产生图像或驱动数字人。生成使用现有 CreativeJob 队列及运行时许可校验，不静默切换 mock。图像支持既有比例参数及有参考图时的 image_edit 功能选择。

运行固定保存修订、项目版本、当前执行者与模型/网关版本。人工节点暂停，创作者明确确认后继续；审片者和时间持久记录。运行与浏览器生命周期独立，离开、刷新不会重新提交模型。并行分支失败或结果未知时暂停新的步骤派发，但继续沿原任务核对已接纳子任务，保留它们的最终身份和结果。结果留在当前项目媒体库，不自动覆盖剪辑或向平台发布。图上状态只显示与当前保存修订匹配的服务器运行。

保存/运行/审片/取消使用原请求回执与 CAS。原请求恢复返回当前状态，不能倒退后来修订；冲突保留草稿，明确核对后才能选择新的保存起点。未知结果仅核对原子任务及原键，不自动新建生成请求；已知异步上游身份可沿原任务查询。停止尽力取消本地子任务，阻止后续派发，无法承诺撤回已开始的上游计算。

## 领域与存储/API

- `modules/workflows/model.go`：有向无环、端口类型、稳定拓扑顺序、重复身份/输入/循环、必需输入与输出可达性校验。拒绝未使用的模型分支，避免无意派发。
- `persistence/workflowrepo`：每项目原子文档，工作流/不可变修订/运行/步骤/回执/私有模型选择记录；文件锁、临时写入、同步和原子替换；PostgreSQL 项目锁、同步提交、迁移屏障及项目外键；损坏数据拒绝读写，不重新初始化覆盖。
- `application/workflow_{http,store}.go`：所有入口经现有安全 handler 的成员、角色、租户和 CSRF 检查；worker 每次推进重新检查当前执行者、当前模型/功能绑定；子任务派发仍经执行 governor 颁发任务许可。凭据不进入图、运行响应或公共回执。
- `api/openapi.json`：project/workflows 的列表、创建、读取、保存修订；修订元数据分页与单项读取；固定修订启动；project/workflow-runs 的列表、详情、人工决定、cancel/reconcile。目录每页20条仅为分页，项目不设工作流/节点/运行次数额度。
- 文件目录为 DATA_DIR/workflows；新增 PG 表 `studio_workflow_projects`，私有 JSONB 与复合项目外键。既有离线 import/export 已接线，缺少旧目录按兼容空集合处理；坏文档使迁移失败。升级必须先备份并停掉所有 API/worker writer，再按现有迁移方式更新数据库与二进制；回退需数据库及 DATA_DIR 匹配，不能让不认识新集合的旧版本继续写入。
- 文件 API 启动流程 worker；PG 独立 worker 启动同一控制器，多实例按项目事务串行推进，子任务沿原幂等键接续。

## 数字人实际改造

`digital_human_files.go` 新增 **studio-avatar-files-v1** 专用模型执行器协议，photo_avatar 与 lip_sync 两条路线均可使用。可信绝对命令、清理后的环境、私有工作目录、私有媒体副本、小型 JSON 控制报文、固定输出文件、拒绝软链接/非普通文件、可取消进程及严格 MP4 全解码校验。程序是部署方信任的本机进程，**不是操作系统沙箱**；不得把用户提供的命令接入配置。

生产数字人链改用路径，FFmpeg 读文件，结果通过 addAssetFile 入库，避免完整媒体 base64/[]byte 往返。移除项目通用 10MiB/30秒输入门槛和前端相同限制，保留有效格式、有效时长、照片至少256像素、视频路线配音不得长于原视频等真实要求。旧 json-v1 默认保留兼容，其10MiB输入/32MiB输出内存边界明确展示；超出时提示部署方切换文件协议，不截断媒体。

文件协议合成不再强制720p/24fps/32MiB：保持原生尺寸（编码要求偶数像素）及帧节奏，用已授权音频替换模型音轨并烧录AI标记。不会凭空产生原生4K细节，也没有把通用 video 模型冒充图音频驱动专用引擎。

形象授权、声音用途声明与现有库来源保护仍有效。增加按口播任务已记录声音确认者重新检查当前成员写权限，在实际进程派发前再次核对；旧任务无可信确认者时安全拒绝新派发。撤销形象后停止新生成和发布在途结果；历史成片保留。未安装引擎或许可声明未确认时仍显示不可运行，许可声明不等于商业许可。

协议与安装见 [数字人口播使用合同](../../../digital-human.md)。Compose、后端及部署环境示例已透传协议和执行超时。默认120秒执行器截止时间和既有 worker 截止时间是运行保护，长任务需要按引擎调度能力配置；本轮没有实现分段推理检查点，不声称任意长任务都能续跑。

## 本轮回归中发现并修正的问题

- 流程最初在任务接纳前调用需要 governor 任务许可的执行检查，导致 model_runtime_denied；改为身份/当前模型版本/绑定预检，实际派发仍由现有子 worker 领取许可，未绕过安全校验。
- 子任务已提交而流程文档未确认时，模型配置撤下曾阻断只读恢复；现在先沿原回执及严格指纹找回已提交子任务，只有新的接纳需要当前模型权限。
- 手机端工具条曾把流程名称输入框挤到不可读；调整为整行字段并加实际宽度断言，三种主题和手机截图复验。
- 全量路由测试发现一个用例把六组主题/语言和十七条路由共用30秒，独立复现还发现作品列表冷启动会加载所有编辑/制作面板。面板改为按需加载，测试按主题/语言及每条路由拆开，原断言和原超时保留，新增流程目录路由覆盖。最终结果见 validation.md。
- 数字人原生测试明确校验错误分类后发现无效引擎MP4被当成素材输入错误；已统一归类 invalid_provider_response，仍删除不完整文件；成员撤销则明确记录 model_runtime_denied。

现有 CreativeJob 提示文本仍有3–2000字符的本地实现边界，画布沿用这一输入合同，不能把它声称为上游原生token窗口或“无限输入”。该边界及真正长输入节点仍需后续改造；本轮未增加项目额度/费用门槛。
