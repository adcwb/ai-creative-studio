## 用户目标与边界

在现有数字人作品空间选择真正可渲染的GLB角色，登记素材/形象许可，选择或通过已配置网关生成文案和配音，再在浏览器播放带基础口型的3D角色。无需将网关密钥交给浏览器，也不默认调用Google/Azure等额外TTS。保留当前C端设计、错误恢复、只读与权限隔离。

这不是照片转写实3D，不是已完成双向实时语音会话或3D成片导出。TalkingHead当前语言模块没有内置中文；现有语音协议只返回音频，没有音素时间戳。首版明确提供音量驱动基础口型，不能称为中文音素对齐或专业口型验收。原生低延迟会话、中文精确音素/viseme对齐及成片录制另列未完成。

## 实施合同

- Web入口沿用 `/digital-humans/3d` 与现有digital-human项目；照片/视频和interactive现有行为保留。3D列表与视频列表共享底层作品，可复用已授权音频；不引入新项目额度。
- 角色配置独立于视频型DigitalHuman：模型来源（固定CC0/私有GLB）、不可变模型SHA/空间/项目、名称、许可和形象声明、登记人、可永久撤销。复用creative文件/PG作用域与blob，不创建另一个执行平台。
- 自定义GLB流式上传，校验GLB2长度/JSON/BIN、无外部URI或脚本/远端解码器扩展，检查兼容标记；真实骨骼/形变兼容仍需在浏览器加载验证。资源仅存本空间/项目私有blob，禁止任意URL模型。格式、GPU能力与进程保护不是产品额度。
- 文件和PG持久化、项目FK、旧数据兼容、blob备份/存储迁移纳入同一改造；不能只写浏览器状态。私有下载校验租户/项目/当前模型授权，不泄露原始blob键。
- 创建/上传/撤销需当前写权限、CSRF、可信Origin和幂等键；响应不明保留原请求，文件刷新后须重新选择原文件，不谎称浏览器保存了原始二进制。
- 文案/配音复用真实creative-jobs与RuntimeModelPicker，分别显式触发；文本候选由用户决定采用，不自动付费链式调用。保留现有模型执行权限与能力校验。
- 播放前校验模型/配音/声音授权与素材来源撤权；授权读取失败停止播放，新派发不得使用撤销素材。已下载到用户设备的内容无法以服务端撤销即时回收，不承诺DRM或云端撤回。
- Three/TalkingHead按需加载，限制DPR/帧率、后台/不可见暂停、及时释放WebGL/音频/Blob URL；移动端默认较低渲染负载，兼容失败清晰提示，无假角色替代。基础口型按实际音频采样RMS驱动jawOpen，整条原声音轨连续播放。

## 领域、接口与当前实现

`creativeDisk.avatars_3d`保存独立形象登记，PG对应`studio_avatar_3d_models`，以tenant/project复合外键约束；配置有不可变SHA、登记人、时间、许可/形象声明、骨架模板及撤销时间。自有GLB以空间/项目/内容证明派生私有blob键；公开DTO不包含blob位置。内置CC0文件随前端分发，登记仍是项目私有状态。

| HTTP入口（前缀`/api/v1/projects/{id}/avatar-3d-models`） | 行为 |
| --- | --- |
| GET / POST根路径 | 本空间项目列表 / 登记CC0 JSON或metadata+model multipart |
| GET `/requests/{key}/result` | 原幂等请求回执；刷新无需再次发送GLB |
| POST `/{modelId}/revoke` | 明确永久撤销；失败不假装完成 |
| GET `/{modelId}/file` | 当前授权下的私有GLB、SHA校验、Range、no-store |
| POST `/{modelId}/playbacks` | 纯授权核对：模型、声音、音频来源及当前成员权限；不派发模型、不计费 |

HTTP合同见`api/openapi.json`的Avatar3D模式与六个operation。上传流式落私有临时目录，GLB二进制不整块驻留后端内存；声明长度、JSON单token及嵌套、允许扩展/外链与accessor数是格式与解析保护，不是业务额度。GLB2自身uint32长度是协议边界。当前只做兼容标记预检，完整骨骼、网格与贴图能否使用以TalkingHead实际加载为准，不能将预检通过标成已验证模型效果。

前端`Avatar3DModels`原请求描述按actor/space/project隔离在sessionStorage，仅包含元数据/文件摘要；文件SHA在1MiB切片中计算。刷新后可查原回执，或重选同样字节重试原键，不保存原二进制。登记结果不明期间不允许换许可或新建另一个付费请求。后端对象名包含SHA，避免相同键不同内容竞争覆盖；元数据与回执同事务提交。对象上传成功但元数据提交中断时可能保留未引用对象，不能因结果不明擅自删除；本轮未新增孤儿自动回收服务。

`Avatar3DStudio`复用真实creative-jobs、模型能力选择、已存在的可恢复音频上传及声音授权。先显式生成文案、人工采用，再显式配音；无mock回退、无隐式收费链。共享digital-human底层作品，3D入口不把网页预览冒充视频成片。既有单请求文案2000字符是当前创作接口输入合同，未新增项目总次数/时长/费用限制。

`Avatar3DStage`延迟加载TalkingHead/Three，在当前浏览器解压模型与解码音频；40ms采样RMS驱动jawOpen，静音闭嘴，音频原时长连续播放。手机默认低负载、有效DPR≤1，标准≤1.5，24/30FPS；后台、离屏、停止、模型/音频/授权切换中止待处理播放并暂停渲染；页面卸载关闭AudioContext、释放GPU与Blob URL。选用/质量切换才加载相应模型；不向文案或语音供应商发送GLB。

开始和音频解码后均核对授权，播放中每2秒纯校验；失败停止。此为正常客户端的检查机制，不能撤回用户已经复制的字节，也不能承诺瞬间撤权、DRM或服务端远程清除设备缓存。旧授权历史保留，撤销阻止新的使用。

## 升级、兼容与恢复

- 文件模式新增可选map，旧快照可打开；新自有模型在既有私有媒体目录/blob中，与元数据一起备份。不要用旧程序写入已有3D数据的快照，旧代码不认识新集合可能丢弃它。
- PG沿用显式`InitPostgres`迁移机制，新表/复合FK与`studio_blobs_key_kind_v2`约束一起在事务和迁移锁下升级；旧blob键仍有效，允许新增`.glb`，其他扩展继续拒绝；新readiness要求匹配结构。必须按既有运维文档停写、备份、运行迁移再启用新API/worker，不能只更换二进制后绕过readiness。
- 本轮仅对隔离本地测试schema迁移，未对生产运行迁移或部署。需要回退时一并恢复匹配版本的代码、数据库、DATA_DIR及对象证明/文件备份，不能只回退前端或API。文件→对象存储→文件的模型SHA与引用往返有协议替身测试；真实S3/OSS环境未验收。
- 撤销是永久状态，不以重新加载绕开；需要新许可时登记新的形象版本。当前没有角色几何编辑器、照片建模器、3D视频录制或3D工作流执行节点。
