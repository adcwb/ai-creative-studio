# 可视化创作流程与数字人

状态：Implementing，本地已有可执行阶段结果，完整规格未完成。详见 [实施记录](implementation.md) 和 [任务状态](tasks.md)。基线 `486ef479b4906aa6c3ddc6a37516d33c0da818de`（第 6–10 项已推送，CI 43475422718 的 25 项检查全部成功）。本包属于随后授权的第 1、4 项；先保留本地，不随上一阶段提交推送。不得把本包的设计内容当作现成功能或供应商验收。

## 创作目标

设计师把反复执行的创作步骤保存为可读、可改的流程：从描述或已有素材开始，调用已配置模型，比较输出，在明确的人工作品选择之后继续制作。导演看到每一步使用了哪份素材、何处停下、下游将受什么影响；失败后沿原任务恢复，避免重复生成。数字人先把已有照片/视频、已授权声音和口播文案衔接为实际可预览、可剪辑、可交付的视频；许可、模型效果及服务可用性始终分别展示。

以 C 端任务语言呈现步骤，不让用户编写代码或理解 Eino 内部状态。1920×1080 桌面提供画布、步骤库与属性栏；窄屏提供同一张图的可访问步骤列表、点选连接、单栏属性与执行进度。保留既有森林/纸张/放映主题、字体、导航、按钮和空/错/恢复状态。不新增成本、项目额度或内容审核就绪门槛。

## N1：创作画布的首个完整闭环

US-C1：新手选择“参考图到出稿”模板，修改描述、连接素材和模型步骤，保存后重载仍保持布局与参数；模板是实际步骤定义，没有预生成假结果。

US-C2：用户运行一个已保存版本，服务端验证图、当前权限和可用能力后自动执行，人工选择步骤停住等待本人确认，继续后沿既有真实生成/媒体任务处理；刷新和 API/worker 重启可恢复原运行。

US-C3：创作者明确重做某一步时，生成新的运行尝试并提示哪些下游需重做；旧运行、采用结果和导出不覆盖。未知结果先核对原任务，不能自动再发付费请求。

FR-C MUST：图为有向无环、端口有类型、连接有明确来源；拒绝环、悬挂端、重复身份及能力不匹配。不能执行任意 JS/Python、任意 URL、shell 命令或注入模板表达式。变量编译复用提示词的安全语义。

FR-C MUST：持久化图内容、画布布局和不可变版本，保存用 CAS/原请求键，运行固定版本及输入摘要；run/node/attempt 与现有子任务一一关联。凭据仅在派发时从当前空间网关读取。用户不具备的模型或资产不可借流程访问。

FR-C MUST：每步派发与人工继续均检查当前成员权限、当前资产授权、当前模型能力；取消或撤权后不派发下游，结果未知不静默重试。既有结果可按历史语义追溯，但不能因此恢复授权。

FR-C MUST：服务端执行与浏览器生命周期独立。持久状态至少区分 queued/running/waiting_review/succeeded/failed/cancelled/unknown；图上看到的状态来自服务端。节点及图数量不设产品配额；分页、请求工作集、队列并发和执行超时如实作为运行保护说明。

首批节点按实际可复用链路逐一落地：描述/变量、项目素材、图像创作、文本处理、现有项目创作任务、人工选择和固定媒体输出。剧本/分镜/音频等不得仅注册名称而声称可运行；每种节点均需单独完成适配与合同测试。自动外部发布和跨集批产不作为首版节点。

领域/API 候选：Workflow、WorkflowRevision、WorkflowRun、WorkflowNodeRun、ReviewDecision。拟放入 `modules/workflows`、`persistence/workflowrepo`、application/workflow_* 与 frontend/features/workflows；接口拟为 project/workflows、workflow revisions/validate/runs、run nodes/decisions/cancel/reconcile。表及文件结构在实施前落到完整请求响应、约束、迁移与恢复验收中，不能临时加在不受约束的浏览器存储。

画布候选使用 MIT React Flow 的基础组件（npm 官方元数据当前为 12.12.1，peer React >=17，本轮已安装并锁定精确依赖），自定义本项目节点和样式，不购买或复制 Pro 模板。浏览器只负责交互，真实执行仍在服务端。Eino v0.7.37 有 Graph/Checkpoint 扩展点，但是否采用必须先用现有异步子任务验证恢复语义；不得为套用框架再建一套重复派发系统。

## N2：真实数字人的执行器与制作闭环

US-D1：选择已有授权形象和声音，配置口播方式，看到匹配的实际执行器/供应商及其原生能力，提交后得到真实生成任务和可剪辑视频。无可用执行器时给出可操作配置说明，不输出幻灯片或假口型。

US-D2：按上游原生输入窗口分段、核对每段授权及版本，沿原异步任务取回结果并重组；失败片段可单独核对或重做。连续性和口型人工审片，不能以格式检查冒充艺术效果通过。

FR-D MUST：区分本地执行器、专用网关协议与通用视频模型。通用 video 声明不证明支持 image+audio 驱动；需要明确适配器及原生输入窗口。DeepSeek 文本模型不能充当数字人驱动引擎。

FR-D MUST：优先用文件/流式输入输出消除旧 base64 工作集门槛，清晰保留可信执行器路径、进程终止、路径隔离、FFprobe、SSRF/下载安全、原始音轨与时码一致性。Linux 与 Windows 均要验证；本地有 GPU/权重不是仓库自动具备的能力。

FR-D MUST：模型原生分辨率、素材质量与后期输出档位分别记录；1K–4K 是合成交付目标时不能声称模型生成了原生 4K。项目不设总时长/次数/费用配额；供应商确有单请求窗口时按其协议适配，不把该限制推广到所有数字人。

FR-D MUST：形象、声音授权均可追溯与撤销，历史与新派发分离；部署许可声明不等于商业许可。接入真实模型之前不得宣称可商用或效果已通过。任何真实付费调用仍需明确授权，本轮测试只用本地合成供应商。

候选专用服务为百炼 `wan2.2-s2v`，不是已完成接入。官方协议要求图片/音频可访问 URL、北京地域、异步任务；文档所述原生 480P/720P 和音频小于 20 秒属于该模型的协议边界。需要确认实际网关是否透传、账号是否授权、临时素材访问/过期/删除语义，以及 Token Plan 是否包含，均不能凭名称推断。未得到这些环境信息时保留“未实测”，不把所有 API key 当作该模型可用凭据。

交互数字人和 3D 数字人需要不同执行合同（实时音视频会话/驱动、三维资产及动作）。先落实视频路线和实际能力目录，再按已授权方向补专门规格与执行器适配；不可通过把占位页换成聊天窗口或静态模型来宣称实时/3D 制作已完成。
