## 修复方式

- 将侧栏分为覆盖整行高度的 `.sidebar` 背景轨道和 `.sidebar-inner` 内容。轨道随实际文档高度延伸；内部使用 `min-height: 100dvh` 与 sticky，保留自然内容高度。
- 桌面视口高度不超过 700px 时，内部取消 sticky，随文档滚动，防止短屏内容被固定位置困住。
- 桌面创作网格使用 `align-items: stretch`，两列取实际内容中更高的一列并对齐底边。创作表单采用纵向 flex，将底部辅助操作推到面板底部；记录空状态占用剩余空间。
- 1050px 及以下维持单列内容顺序；700px 及以下侧栏变为顶部栏。记录、长描述及所有操作保留在文档流中，没有加入固定容器高度、内容裁切或隐藏滚动。

## 图像服务状态与历史来源

页面读取 `GET /api/v1/capabilities` 决定当前创建能力。模拟模式明确显示非 AI 图像；真实模式仅说明本地配置就绪和可能计费，不声称已验证远端凭据、额度或画质；缺少配置及接口读取失败时暂停新的创建与重试，保留历史列表、详情、素材查询和保存。

能力未知或不可用时，前端不发送创建或重试 POST，包括响应丢失后的重发。草稿与原幂等键保留到能力恢复；用户查看当前 provider 与费用提示后可再次明确提交。完整输入及目标路径未改变时，网络重试沿用原键；如果原请求尚未被接受，重发可能成为首次创建，因此不把重发包装为只读查询。

每个创建或重试请求在 JSON 中另附页面当前能力的 `expected_provider` 与 `expected_model`。这两个字段仅作为 HTTP 请求的配置预期元数据，不加入用户创作输入或前端幂等指纹。后端在新任务入队前原子核对配置；不一致返回 `409 provider_changed`，前端保留草稿与原键、重新读取能力并要求用户再次点击，不自动重发。已接受请求的同键重放仍返回原记录，避免配置变化让未知提交产生额外任务。

每条任务、素材的状态文字、结果标签和替代文本根据该条记录固化的 `provider` 渲染。原模拟结果仍为“模拟图像 · 非 AI 生成”；真实 provider 记录标注“OpenAI 图像服务返回”。详情展示后端返回的模型、实际 MIME 和实际尺寸，不从当前服务能力推断历史内容。重试成本说明以当前服务模式为准；原真实请求超时、中断或返回无效产物时，另说明上次请求可能已计费。

最终 provider 浏览器检查通过：缓存模拟模式切换真实配置被 `409 provider_changed` 阻止并要求手动再次提交；能力读取未知状态没有创建 POST；恢复后保留原键；历史 SVG 与 PNG 来源正确区分，详情保留模型 / MIME / 尺寸，PNG 可保存及重启读取。证据为 `/tmp/studio-provider-evidence-Fu2hn3/evidence.json`，其中上游明确是 **loopback fake HTTP 与合成 PNG，没有调用官方 API**。相关图只证明协议和业务流程，不证明真实 AI 画质、凭据有效性、远端计费结果或服务可用性。
